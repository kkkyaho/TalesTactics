# 메인 7~20화 확정 보상 다양화

2026-11-06~10, develop의 73a0557 이후 작업. 메인 7~20화 확정 보상 다양화와 실제 Unity·Windows 전후 검증을 완료했다. 사용자 음원과 이를 포함한 소스·빌드는 로컬에만 보관하며 main 반영·원격 푸시·공개 릴리즈는 수행하지 않는다.

[기존 후보 A](../StandardWeapons/reward-options.md)의 배치를 CrossoverCampaign.Chapter의 단일 표에 적용했다. 출전 전 미리보기와 결과 지급이 이 표를 공유한다. 메인 최초·재클리어 모두 변경된 확정 장비를 1개 지급하며, 재클리어 EXP·골드 계산과 기존 수량 상한은 유지한다. 기존 보유 메달과 장착 장비를 교환하거나 이미 완료한 화의 보상을 소급 지급하지 않는다.

새 아이템·가격·능력치·골드·EXP·무작위 추가 드롭·적 수치·개인 이야기·과거 6장 보상은 변경하지 않는다. Content 에셋은 다시 생성하지 않는다. 일반 병과 무기는 이미 1화 완료 후 구매할 수 있으므로 이 배치가 항상 새 장비 획득이나 성능 상승을 뜻하지는 않는다.

## 경제적 영향

확정 보상 20개의 미장착 매각 가치는 기존 4,800G에서 3,850G로 950G 줄어든다. 1~6화의 1,440G는 같고 7~20화는 3,360G에서 2,410G로 바뀐다. 이는 현재 상품 가격을 적용한 산술이며 실제 소지금·전투 효용이나 사람의 체감 균형과 같지 않다. 첫 클리어 순수 골드 12,900G와 시작금 300G는 유지한다.

Windows 전후 검수는 같은 seed17·고정 편성/구매 정책을 사용한다. 보상으로 얻은 장비가 이후 구매·장착·전투에 영향을 줄 수 있으므로 그 결과까지 무조건 같다고 요구하지 않고 차이를 보고한다. 각 거래 가격·잔액·재고·지급·저장 재로드는 별도로 검증한다. 전투 시간은 자동 진행 수치이며 사람의 플레이 시간이나 난이도 평가가 아니다.

## 실패 이력과 보존

처음 Scene Backup Detected 안내와 Windows 제어 도구의 샌드박스 오류로 대기했다가 사용자가 안내를 처리한 뒤 재개했다. 최초 EditMode1개 실패는 기존 atlas 장비에 개별 Sprite가 있어야 한다는 새 검사의 잘못된 전제였고 실제 EquipmentArt 경로를 확인하도록 고쳤다. 신규 PlayMode meta의33자리 GUID를 정상32자리로 고쳐3개를 발견했다. 이후 전체0개 실행2회는 미실행으로 보존했으며 도메인 재로드 뒤 실제290개를 실행했다.

첫 전체 PlayMode는289/290이었다. 기존 공격 모션 검사가 LateUpdate 이전 위치를 읽을 수 있어, 테스트만 고정 시간 간격과 프레임 완료 후 판정으로 보정했다. 기존 위치 허용치를 유지하고 공격 시계 재시작·반복 스핀 시계 유지·대기 연출 복귀 검사와 실패 진단을 추가했다. 당시 실패의 정확한 원인은 시간 기록이 없어 확정하지 않는다. 제품 모션 코드는 바꾸지 않았으며 표적1/1 뒤 별도 전체290/290을 통과했다. [전체 실패·복구 이력과 해시](Validation/validation-history.json)

검증으로 갱신된 폰트·CSV·임시 백그라운드 설정은 생성본을 보존하고 작업 시작 바이트로 복원했다. 기존 사용자 수정12파일, 최종 제품/검사6파일, 빌드 입력2,320파일과 기록한 Editor 상태가 일치한다. [복원](Validation/protected-restoration.json) · [빌드 입력/실행본 연결](Validation/after-binary-source.json) · [최종 대조](Validation/final-state.json)
