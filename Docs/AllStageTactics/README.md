# 전체 전장 전술 구성

메인 20화와 개인 전투 20개에 지형·진입 경로·목표 배치를 적용한다. 먼저 완료한 메인 1~3화를 유지하고, 후반 17화와 개인 구조/시련 20개를 추가했다. 개인 이야기 10개는 대화로 진행한다. 기존 성장·장비 보상 기능은 그대로 연결한다.

## 전장별 선택

- 메인 4·5·15화는 전장에 배치한 신호와 보스가 함께 목표다. 5화의 두 구조 지점은 병력을 나누거나 한쪽부터 공략할 수 있다.
- 6·8·12·19화는 장치 방어선과 보스를, 7·13·18화는 분산된 신호와 보스를 중심으로 진행한다.
- 9·16화는 실제 퇴로가 별도로 있다. 보스를 처치하지 않고 목표를 마칠 수 있으며, 16화의 선두 생존 조건을 유지한다.
- 10·14·17화는 보스 결전이다. 수집 목표를 추가하지 않고 고지·계단·다리로 접근 경로를 구분한다.
- 11화는 서쪽 전선에서 동쪽 전선으로 전환하는 기존 규칙과 예비 부대를 유지한다.
- 20화는 세 귀환 신호·세 장치·보스의 세 단계를 모두 마쳐야 한다.

각 개인 구조 전투에는 서로 다른 벽·다리·높이와 서쪽/동쪽 선행 선택이 있다. 개인 시련은 기존의 실제 행동 조건을 유지한다. 크레스의 공격·치유·방어와 순서 있는 신호, 민트·시온의 유효 회복 3회, 티아의 노래, 제이드의 준비 취소, 벨벳의 흡혈, 알펜의 HP를 지불하는 화염검, 키사라의 방어 중 실제 피격이 해당한다. 나탈리아와 파라의 고유 목표도 보존한다.

## 표시와 저장 연결

출전 전 미니맵, 경로 선택 안내, 전장의 신호·장치·출구·계약 문양·소환진이 실제 배치를 따른다. 보호 신호를 사용하는 보스 공격과 전투 예측도 같은 좌표를 사용한다. 이야기 배경은 해당 장의 전장 주제와 연결하고, 개인 대화는 야영지 이야기로 표시한다.

기존 중단 저장에는 새 `TacticsRevision` 값이 없으므로 0으로 읽어 이전 지형·목표·소환 위치를 복원한다. 새 전투는 1을 사용한다. 저장 위치를 배치하기 전에 원래 맵을 복원하며, 재시도와 되감기에서도 버전을 유지한다. 중단 저장·시작 상태·되감기 이력의 지형 버전이 서로 다르면 잘못된 저장으로 거부한다. 메인 1~3화의 기존 `OpeningRevision`과는 별도로 관리한다.

## 검증

실제 Unity 6000.6.0f1 전체 EditMode **703/703**을 통과했다(64.68초). 전체 PlayMode는 **299/300**(1211.52초)이며, 검수 중 보낸 Pipeline 상태 조회의 시간 초과 로그가 섞인 이동 검사 1개를 소스 변경 없이 재실행해 **1/1**(38.37초) 통과했다. 이를 단일 전체 300/300 실행으로 합산하지 않는다.

이후 전체 진행 자동 검수에서 티아의 홀리 송 습득 전 반복 방어를 발견해, 검수 전용 코드 2개에서 실제 출전·성장과 시련 행동 선택을 보완했다. 제품 규칙·검사 소스·나머지 408개 소스는 동일하다. [실패·재검 이력](Validation/validation-history.json)과 [최종 소스 대조](Validation/test-build-source-match-final.json)에 범위를 구분했다.

최종 일반 Windows 빌드(54.92초·오류0·경고7)와 REVIEW 빌드(42.60초·오류0·경고6)는 성공했다. 경고는 기존 Pipeline 설정과 검수 API/지시문 안내다. 각 빌드의 3,055개 입력 해시는 빌드 전후 일치하며 실제 결과·실행 파일·런타임 DLL과 연결했다.

최종 Windows REVIEW 실행은 **전체50개(전투40·대화10), 38,833검사, 저장 재로드391회**를 통과하고 종료 코드0으로 끝났다. 180PNG·100저장 JSON·전용 무기10개·최종6,400G와 보상 중복 방지까지 확인했다. [실행 결과](Validation/windows-campaign-summary.json), [보상·재고 대조](Validation/windows-reward-economy.json), [일반 실행본의 검수 코드 제외](Validation/windows-player-type-isolation.json). 일반 실행본은 빌드와 코드 분리만 확인했으며 이번 작업에서 실행하지 않았다.

보호 파일12개와 실제 저장·설정9개는 작업 시작 상태를 유지했다. 전체 작업 중 테스트 산출물인 StorageTests 파일65개·폴더35개가 추가되고 TestResults.xml이 변경됐다. 삭제는 없으며 사용자 트리 전체가 불변이라고 표현하지 않는다. 보존 비교 도구의 변수 충돌은 원본 실패 기록과 스냅샷을 남긴 뒤 수정·재평가했다. [최종 보존 기록](Validation/final-preservation.json), [Editor 복원](Validation/editor-state-comparison.json).

[대표 화면4장](Evidence/visual-review.json)을 육안 확인했다. 자동 진행은 Standard·seed17·4배속이며 개인 이야기별 하나의 경로를 선택했다. 사람의 난이도·재미·목표 이해도, 모든 분기 조합과 대화 도중 프로세스 재시작을 검증한 것은 아니다. 기존 사용자 수정·미추적 원화를 포함한 작업 폴더에서 검증했으므로 깨끗한 클론 재현성도 별도 확인이 필요하다.
