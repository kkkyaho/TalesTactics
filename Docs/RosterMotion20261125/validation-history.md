# 검증 과정과 재검사

## 검사 실행 환경

초기 연속 PlayMode 요청과 전체 요청 일부는 실제 검사 0개로 종료했다. 0개는 통과로 계산하지 않았다. 설치된 Unity Test Framework의 어셈블리 목록이 빈 nonnull 상태로 남아 재탐색을 건너뛰는 것을 확인했다. 기존 DisableDomainReload 설정을 유지한 채, 정지된 검증 Editor의 해당 메모리 캐시만 null로 되돌렸다. 제품·테스트·패키지 소스·프로젝트 설정은 변경하지 않았다.

공식 TestRunnerApi에서 전체321개를 발견하고 실행했다. Play 진입 시 끊긴 결과 수집 콜백은 진행 중인 동일 실행에 다시 연결했다. 이후의 최종 결과 트리와 공식 XML에서 전체 이름·개수·판정을 대조했다. 부분 진행 알림을 전체 결과처럼 계산하지 않았다. 첫 실행 요청·0개 결과·캐시 전후·패키지 원문 해시는 로컬 Logs에 보존했다.

## 실제 전체 검사와 별도 재검사

전체 EditMode는718/718 통과했다. 전체 PlayMode는321개 중320개 통과,1개 실패였다. 실패한 기존 AllCharacterPosesRenderInFourCameraDirections를 제품·테스트 변경 없이 단독 재실행해1/1 통과했다. 이를 단일 전체321/321 통과로 표현하지 않는다. 정확한 실행 시각·시간·개별 결과 대조와 근거 해시는 [EditMode](Validation/editmode.json)·[PlayMode](Validation/playmode.json)를 따른다.

실패 검사는 새 roster 모션 대신 기존 Initialize 경로의10개 배우를 사용한다. 기존 피격 모션은0.28초 이후 대기 원화로 복귀하지만 검사는 WaitForSeconds(0.12)와 프레임 끝 대기 뒤 특정 피격 원화를 기대한다. 해당 검사 본문과0.28초 복귀 조건은 이번에 변경하지 않았다. 최초 실패에서 실제 경과 시간을 기록하지 못했으므로 느린 프레임으로 관측이 늦었다는 설명은 가능한 원인이며 확정 진단이 아니다. 실패 원문과 재검 원문을 모두 보존했다.

## 실제 전장과 캡처

전장 연결 검사의 첫 회차는 방향 값 변경 후 실제 Board.Sync를 호출하지 않아7행에서, 다음 회차는16스테이지의 예비 동료를 활성 배우로 기대해683행에서 중단했다. 검수 도구를 수정하고 제품의 실제 비활성 예비 동료5명을 먼저 확인했다. 렌더링 연결 검사를 위해 임시 세션의 예비 플래그만 해제한 뒤 모든 원래 상태를 복원했다. 최종2,280/2,280 결과는 자연 합류·정규 출전 자격을 검증한 결과가 아니다. [세 회차 구분과 최종 결과](Validation/stage-matrix-summary.json).

초기 촬영 도구의 Play 종료 수명과 프레임 직렬화 누락은 검수 도구에서 수정했다. 최종 BeforeFinal/AfterFinal20회차의 기록 프레임5,539개와 실제 PNG5,539개를 대조했다. 이전 시도는 최종 화면 증거로 사용하지 않았다. [실제 모션 관측](Validation/motion-summary.json).

갤러리의 초기 시간 슬라이더는 초 단위 반올림으로 끝 프레임 직전 장면을 고르는 경우가 있어 정밀도를 보완했다. 최초 실패 자료를 남긴 후 최종60개 조작과 원본 이미지 읽기·해시 일치를 확인했다. [갤러리 검증](Validation/gallery-verification.json).

## 빌드 산출물 검사

Windows 실행 코드 검사 도구의 첫 호출은 시작 시각의 UTC 오프셋이 빠진 입력을 거부했다. 원문을 보존하고 정확한 ISO UTC 입력으로 다시 실행해14개 검사를 통과했다. Android의15개 실행 코드 검사와 APK 서명·ARM64·가로 화면·ZIP 검사도 통과했다. 검사 도구 입력을 보정했으며 제품 코드를 변경한 것은 아니다. [빌드·시간 범위](Validation/build-summary.json) · [산출물 대조](Validation/artifact-verification.json).

## 증거 해석

자동 관측과 에이전트가 실제 이미지를 직접 확인한 대표 장면은 구분한다. 실제 전장80장과 모션5,539프레임 전체의 시각 검토를 완료했다는 주장은 하지 않는다. 직접 본 고유 대표 장면239개와 시각 품질의 한계는 [검토 기록](Validation/visual-review.json)·[품질표](Validation/visual-scorecard.md)를 따른다. Editor 가로 화면·APK 생성은 휴대폰 설치나 실제 기기 플레이 성공을 의미하지 않는다.
