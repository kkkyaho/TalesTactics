# 동료 전체 모션 확대 — 2026-11-25

플레이 가능한 동료10명(크레스·민트·파라·티아·제이드·나탈리아·벨벳·알펜·시온·키사라)의 기본 대기·호흡·눈감음·기본 공격·피격에 방향별 원화 모션을 연결한다. 알펜 시범32포즈를 유지하고9명288포즈를 추가해 총320포즈를 모든 전장에서 사용한다.

## 적용 내용

- 같은 발 위치를 기준으로 숨 쉬고 짧게 눈을 감으며, 동료마다 대기 시점에 차이를 둔다.
- 기본 공격은 준비→타격→회수로 이어지고, 피격 뒤 새 대기 그림으로 돌아온다.
- 캐릭터별 머리–발 높이에 맞춘 크기와 HP바 위치, 기존 접촉·몸 그림자를 사용한다.
- 기존 전용무기 모습과 고유 기술·보행·방어·사망 동작, 전투·성장·저장 규칙을 보존한다.
- PC와 Android가 같은 원화·모션 코드를 사용한다. 지형은 기존6화 시범 범위를 유지한다.

적·보스의 새 원화, 전용무기를 든 새320포즈, 모든 고유 기술의 새 프레임은 이번 범위에 포함하지 않는다.

## 원화와 정렬

새18장 PNG는 생성 도구의 원래 픽셀·alpha·해시를 그대로 보존했다. 요청 해상도와 실제 출력 해상도는 구분한다. 대부분1254×1254, 민트/티아 대기는1261×1247, 시온 대기는1262×1246이다. 각 이미지의 정확한 요청문·해시·원본 식별자는 art-{캐릭터}.json에 기록한다.

시트를 일정한 사각 격자로 잘라 무기 끝을 잃지 않도록 실제 포즈별 투명 영역을 측정했다. 네 방향의 머리와 양발 기준점을 오버레이로 검수하고, 지팡이 장식/창과 머리, 정강이와 발바닥의 잘못된 자동 후보를 수정했다. 검수 좌표는 [5명](landmarks-reviewed-five.json)·[4명](landmarks-reviewed-four.json), 실제 Unity 가져오기 입력은 [art-layout.json](art-layout.json), 크기 근거는 [scale-calibration.json](scale-calibration.json)에 있다.

대기·공격 시트마다 기존 정면 자세의 머리–발 높이에 맞춰 PPU를 계산했다. 발 피벗과 HP바 기준점은 포즈별 좌표를 사용하며 기존200개 머리 기준점은 유지한다. Unity의 Sprite 편집 API가 새 metadata를 작성하고 재실행 때 Sprite 참조를 보존한다.

## 실제 검증

실제 Unity6000.6.0f1 [EditMode718/718·23.50초](Validation/editmode.json)를 통과했다. [전체 PlayMode320/321·733.25초와 동일 소스의 단독 재검1/1·10.59초](Validation/playmode.json)를 구분해 기록한다. 최초 실패는 기존 네 방향 피격 원화 검사이며 재검에서는 통과했다. 실제 관측 경과 시간이 없어 원인을 확정하지 않았고, 단일 전체321/321 통과로 표현하지 않는다. [실패·재검·검수 보완 이력](validation-history.md).

전후20회차의 실제 모션 PNG5,539개와 실제 전장80장, 훈련을 포함한57개 스테이지×10명×4방향 연결2,280/2,280을 확인했다. 전장 연결은 렌더링 확인용 임시 편성으로 합류·정규 출전 자격을 우회했고,16스테이지 예비 동료5명의 원래 비활성 상태를 확인한 뒤 임시 플래그를 복원했다. 자연 합류 규칙의 전체 플레이 검증으로 해석하지 않는다. [모션](Validation/motion-summary.json) · [전장 화면](Validation/actual-board-summary.json) · [스테이지 연결](Validation/stage-matrix-summary.json).

대표 장면239개(모션195·전장44)를 직접 확인했다. [공개 전후 갤러리](Evidence/gallery.html)는 원본66장을 그대로 제공하며 떨어진 순간을 연속 동작처럼 재생하지 않는다. 로컬 연속 갤러리는 실제 프레임을 참조하고60개 조작을 검증했다. [직접 본 장면과 한계](Validation/visual-review.json) · [시각 품질표](Validation/visual-scorecard.md) · [갤러리 검증](Validation/gallery-verification.json).

BuildReport 기준 Windows 빌드101.32초·오류0·경고4, Android 빌드197.83초·오류0·경고6에 성공했다. 이 시간은 BuildPipeline 자체 기록이며 전후 원화 변환·설정 복원까지 포함한 전체 대기 시간과 구분한다. 두 빌드 전후에 이번 변경83파일의 바이트를 대조하고 새9명 및 기존 알펜의 시트20장·프로필10개가 실제로 포함됐는지 확인했다. 실행 코드의 검수/Editor/테스트 참조 제외와 APK 서명·ARM64·가로 화면·ZIP 무결성 검사를 통과했다. APK 정렬 검사는 ZIP4바이트 정렬이며 네이티브 ELF 페이지 정렬 검사와 구분한다. [빌드](Validation/build-summary.json) · [산출물 검사](Validation/artifact-verification.json).

플레이어 실행 로그를 제외한 기존 사용자 트리5,597파일·실제 저장/설정9개·원래 수정35개(ROOT12/PUBLIC23)·기존 원화946개·기존 APK6개를 보존했다. 이번 검사로 추가된 StorageTests65파일·35폴더는 원문을 보관한 뒤 정리했고 이전 검사 XML과 진단 CSV를 복원했다. 별도 검증 Editor의19조건도 시작 상태로 되돌렸다. [보존 검사](Validation/protection-summary.json) · [Editor 상태](Validation/editor-state.json).

## 남은 플레이 검증

휴대폰 연결이 없어 실제 Android 설치·터치·앱 복귀·발열·지속 성능·음원 재생은 별도 확인이 필요하다. PC의 자동 검사·Editor 화면과 일반 Windows 실행본의 직접 플레이도 구분한다. 원화와 소스는 develop에 반영했다. 이후 사용자의 APK 다운로드 요청으로 사용자 제공6곡을 제외한 최신 APK를 공개했으며 [다운로드·검증](../Android/DOWNLOAD.md)을 따른다. Windows 실행본과 사용자 제공 음원의 공개 제한은 유지한다.
