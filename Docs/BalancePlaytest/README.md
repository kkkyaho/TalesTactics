# 7번 — 사람 플레이 기반 난이도·보상 검수

상태: **사용자의 1장 플레이 확인, 전 장 균형 검수는 남아 있음**. 2026-10-07 사용자가 테스트를 진행했다고 알리고 다음 단계 진행을 요청했다. 격리 기록에서 6인 편성의 1장 승리·420G 저장을 확인했다. 장별 평점/의견은 비어 있어 만족도나 6장 전체 완주로 해석하지 않는다. 상세 증거는 user-test-summary.json. 사용자 요청에 따라8번 보강으로 진행하며 적 능력치·EXP·가격은 유지한다.

## 현재 증거와 우선 확인할 점

- 6장×3편성 자동 전투18행 중15승/3패. 기본3인(크레스·민트·파라)은2/4/6장에서 패배했고 두6인 편성은 전 장 승리했다. 출전 화면은6인을 권장하지만 기본 선택은3인이다. 실제로 사용자가 부족한 편성으로 오해 없이 출전하는지 확인한다.
- 새 캐릭터는 대기 중 EXP를 받지 않는다. 같은6인으로 초회 진행하면 장별 진입 Lv1/2/3/4/5/7, 6장 후Lv9다. 후반 교체 캐릭터의 육성이 번거로운지 확인한다. 이는 현재 설계이며 자동으로 따라잡기 EXP를 추가하지 않는다.
- 시작300G, 거래 없이6장 완료하면2140G. 각 장 확정 장비가 있으므로 특정 구매/반복 사냥 없이 진행 가능한지, 장비 획득이 만족스러운지 확인한다.
- 5장 반복의 확정 장비 매각 포함 기대 가치는570G, 6장은555G다. 실제 지급 골드는210/280G이고 추가 드롭은 확률이다. 이것만으로 경제 오류로 판단하지 않고 반복 동기와 보상 체감을 확인한다.
- 기본 SPD/AI와 CT/Utility 각각6장+재실행은 통과했다. 자동 계획기의 승리·턴 수는 사람의 난이도·플레이 시간·재미를 증명하지 않는다.

## 격리 테스트 실행

프로젝트 루트 PowerShell에서:

```powershell
./Tools/StartBalancePlaytest.ps1
```

기존 개발 플레이어의 수동 검수 모드로 실행한다. 새 GUID별 ManualReviews 폴더에 저장·설정·성능/상태 기록·피드백 CSV를 분리한다. 자동으로 전투하거나 능력치/드롭을 주입하지 않는다. 일반 campaign.json과 슬롯2/3을 수정하지 않는다. 해당 실행의 RunId와 ResumeCommand를 보관한다.

```powershell
./Tools/StartBalancePlaytest.ps1 -RunId <출력된32자리RunId>
```

같은 테스트 저장으로 재실행한다. 진행 중에는 F5 → 중단 저장 후 종료하고, 재실행 뒤 F5에서 이어간다. 중단하지 않은 진행 중 전투는 복원되지 않는다. 실행 전·후 사용자 파일 해시는 manifest와 비교한다. 이전 performance/hardware는 재실행 전에 별도 사본으로 보관한다. 상태 로그의 각 실행 시간은0초부터 시작하므로 실행별 log/manifest와 함께 해석한다.

## 플레이 순서

1. 먼저1~2장을 새 저장에서 진행한다. 입문 연습·6인 편성·상점/장비·기술/회복을 평소처럼 사용한다. 장 시작 편성과 레벨, 재도전 횟수, 대략적인 시간을 기록한다.
2. 각 장에서 어려움/지루함, 적 역할을 알아차렸는지, 승리 보상의 만족도를 적는다. 불편한 순간은 F12 캡처 또는 장/상황 설명으로 남긴다.
3. 3~6장으로 이어가며 신규 캐릭터를 바꿔 썼을 때의 레벨 차이와 장비 구매 필요성을 확인한다. 막히면 임의 반복 사냥 전에 어디서 막혔는지 기록한다.
4. 직접 입력한 feedback.csv 또는 대화로 의견을 전달한다. 빈 항목은 평가 없음이며 만족/통과로 취급하지 않는다.

## 피드백과 완료 기준

필수: 장 번호, 출전 캐릭터/레벨, 시도 횟수, 어려웠거나 늘어졌던 상황. 선택: 난이도1(쉬움)~3(적당)~5(어려움), 진행 속도1(느림)~3(적당)~5(빠름), 보상1(부족)~3(적당)~5(과함).

사람의 관찰 → 재현/원인 구분 → 필요한 수치 또는 안내 조정 → Unity/캠페인 회귀 → 사람의 재확인 순서로 진행한다. 사람의 의견이 없는 현재는7번을 완료로 표시하지 않는다. 자동 검증만으로 난이도·보상 최종 튜닝 완료를 선언하지 않는다.
