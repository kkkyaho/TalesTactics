# 전장 지형 아트

승인된 유적·협곡·관측소·수문 시안의 석재, 원경, 장식과 깊이 표현을 기존 6장 전장에 연결하는 작업이다. `Concepts/`는 생성 시안, `chapter*.png`는 Unity Game View의 실제 실행 캡처다. 두 종류를 혼동하지 않는다.

## 구성

- 장별 1672×940/941 원경 6개. 창 비율에 따라 원경을 잘라 채우며 가로·세로를 따로 늘리지 않는다.
- 1254×1254 연속 바닥 4종. 월드 좌표로 한 장의 석판 무늬를 이어서 타일마다 같은 문양이 반복되는 현상을 줄인다.
- 1254×1254 협곡 전용 암벽. 월드 좌표로 옆면을 연결하고 윗면은 위에서 투영해 줄무늬로 늘어지는 현상을 피한다.
- 석재·물·금속 16종 아틀라스, 투명 식생 16종과 건축 장식 16종. 모두 이번 작업에서 imagegen으로 생성했다. 외부 게임의 원본 이미지·음원은 사용하지 않았다.
- 외벽 구조·계단·절벽은 재질별 합쳐진 입체 메시다. 외벽의 조각 아치는 2172×724 회화 텍스처를 연속 UV로 연결한다. 기둥·황동 천문기구·수문 장식은 캐릭터와 같은 카메라 대응 2.5D 스프라이트다.
- 방향별 명암, 지형 깊이 음영과 장식물 접지 그림자, 움직이는 수면·낙수. 장식은 충돌체를 만들지 않는다.

## 규칙과 저장

맵 좌표·높이·장애물·이동 비용·출발 위치·적 수·전투 규칙·저장 형식은 변경하지 않았다. 따라서 시안 속 자유로운 지형 배치를 그대로 복사한 맵은 아니다. 카메라 회전·확대·이동/위험/방향 표시와 기존 중단 전투에 같은 아트를 사용한다. 상시 격자는 추가하지 않았다.

`PixelBattlefield`는 런타임 재질·메시·스프라이트를 소유하고 보드 재생성 시 해제한다. 게임 RNG 대신 좌표 기반 변형을 사용한다. `TerrainGeometry`는 충돌체 없는 장식 메시만 생성한다. `Terrain.shader`는 캐릭터용 재질과 분리되어 있다.

원본 생성 PNG를 축소 재저장하지 않았다. 실제 출력은 재질/식생/바닥1254×1254, 건축 장식1230×1278, 외벽2172×724, 원경1672×940/941다. Unity 임포트는 원본 해상도, 무압축, 바닥/장식/외벽 밉맵과 8배 이방성 필터를 사용한다. `Tools/ImportTerrainArt.cs.txt`로 같은 설정을 적용할 수 있다. PNG 파일 해시는 `assets.json`을 따른다.

## 검증

- 일반 Windows 빌드 **33.222초, 오류0, 기존 패키지 안내3건** 성공(`windows-build.json`). 실행본은 `Builds/WindowsTerrainArt/TalesTactics.exe`이며 폴더 전체가 필요하다. 개발 검수 타입 제외와 Runtime DLL SHA256을 확인했다(`windows-assembly.json`). 안내3건은 Pipeline 런타임 미설정과 URP 내부 디버그 셰이더2종 stripping으로, 새 지형 셰이더의 경고가 아니다.
- 개발 검수 빌드 **38.191초, 오류0/기존 안내3건** 성공. 별도 GUID 저장 경로로 Windows 프로세스를 실행해1장26턴·26이동·22공격, 입문 연습·상점·장비와 승리/저장 흐름을 통과했다(12.24초, 종료 코드0, 오류 로그0, `windows-player-review.json`). 숨겨진 검수 창의 캡처는 시각 증거로 사용하지 않는다. 일반 배포 빌드의 독립 수동 플레이 검수와 구분한다.
- 빌드 패킹 목록에서 신규 PNG15종과 지형 셰이더 포함을 확인했다(`windows-packed-art.json`). 최종 화면/Windows 검수 구간에 사용자 저장·백업·설정 파일의 해시가 유지됐다(`user-save-check.json`). 기존 실행 중인 사용자 게임은 종료하지 않았다.
- 최종 실제 Unity PlayMode **121/121(221.8초)** 통과(`playmode.json`). 새2개 검사는6장 지형·이동 비용 불변, 네 방향 타일 선택, 게임 RNG 불변, 재시작 후 소유 메시/재질/스프라이트 해제를 다룬다. 초기 전체 검사의 기존 장식 이름 기대값1건 실패는 이름을 갱신하고 재검사했다(`playmode-initial.json`, `playmode-final-scenery.json`). 이후 최종 전체121개를 다시 통과했다.
- 코어 규칙 변경이 없어 EditMode/ManagedChecks는 이번에 재실행하지 않았다. 이전 EditMode202/202 결과와 구분한다.
- 실제 Unity API 참조 Runtime/Editor/EditMode/PlayMode4개 컴파일 통과(`api-compile.txt`). 지형 셰이더의 Editor 진단0(`shader-diagnostics.json`).
- 6장 × 1024×768/1920×1080/2560×1080 × 카메라0/90/180/270도 **72개 고유 조합** 통과. 작은 창은 글자130%, 다른 창은100%. 모든 이동 가능 타일의 화면 좌표→타일 선택 불일치0, 화면 밖 활성 버튼/HP바0, TMP 넘침0. 실제 프레임 진행을 확인한 검수다.
- 마지막 협곡 재질 보강 뒤3장12조합을 다시 실행해 다른 장60조합과 합쳤다. `canyon-final-matrix.json`은 해당 재검사이며 `camera-matrix.json`이 최종72조합이다. 중복 합산하지 않는다.
- PNG10장은 실제 Editor Game View 캡처다. 전체6장과 작은 창3장, 1장 초점 확대1장이다. 초기 외벽의 단순한 검은 아치를 조각 재질로 교체했고, 협곡 윗면의 투영 늘어짐도 수정 후 재촬영했다.

자동 기능 검사 통과가 시안과의 미적 동등성을 증명하는 것은 아니다. 시안의 자유로운 지형 배치와 조명 전체를 그대로 재현한 것은 아니며, 원경은 고정된 회화로서360도 공간을 재구성한 환경은 아니다. 다른PC/DPI 및 장시간 GPU 성능 검수는 이번 범위에 포함하지 않는다.
