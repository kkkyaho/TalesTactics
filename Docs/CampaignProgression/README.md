# 메인 20화 성장·보상 연속 감사

2026-10-21. 현행 **경계를 잇는 의지 메인 1–20화**를 새 격리 저장에서 이어 진행했다. 구 6장 독립 전투 결과와 구분한다. 합류 훈련을 쓰지 않는 주력 편성, 합류 훈련을 쓰는 주력 편성, 동료를 교대하며 합류 훈련을 쓰는 편성 모두 코어 명령 시뮬레이션에서 20화를 완료했다. **60전투·저장 후 재로드 일치 123회**이며, 사람의 캠페인 완주나 밸런스 최종 승인 결과는 아니다.

## 수정한 오류

1. **새 캠페인에서 상점 7종이 끝까지 잠기는 문제.** 에셋의 기존 `chapter1/4/5` 요구 조건은 유지하고, 대응하는 `crossover.chapter1/4/5` 완료도 인정한다. 구 저장의 해금을 보존하고 새 저장에 폐기된 장 완료 플래그를 추가하지 않는다. 안내는 현재 메인 화수로 표시한다.
2. **합류 훈련 저장 실패 후 새 캐릭터 기록이 메모리에 남는 문제.** 실제 저장에 실패하면 새로 만든 기록도 제거하며, 기존 캐릭터의 레벨·EXP·해금 기술도 이전 상태로 복원한다. 실행할 필요가 없는 훈련은 새 기록을 만들지 않는다.

[수정 전 실제 카탈로그·코어 확인](Validation/baseline-catalog.json)에서 메인 20화 완료 플래그를 가진 새 저장도 장비 7종이 잠기고, 훈련 저장 실패 후 메모리 비교가 불일치했다. [수정 후 확인](Validation/fixed-catalog.json)은 잠금 0종과 실패 전후 메모리 일치를 기록한다. 이 두 확인은 격리된 메모리에 완료 플래그를 명시한 조건 검사이며, 아래 연속 캠페인 실행과는 별개다.

장비 가격·능력치, EXP·골드·드롭, 캐릭터·적 수치는 이번 작업에서 변경하지 않았다.

## 확인된 성장·콘텐츠 특성

**합류와 출전.** 1화 크레스·민트 2명, 2화 알펜·시온을 포함한 4명, 3화 파라까지 5명, 4화 티아·제이드·나탈리아까지 8명, 5화 벨벳·키사라까지 10명이 합류 가능하다. 출전 상한은 6명이므로 감사의 출전 인원은 2→4→5→6명이다. 게임에서는 기존 편성을 자동으로 새 동료까지 채우지 않는다. 이번 감사기는 정책에 따라 편성을 직접 정했으므로 사용자가 합류를 알아보고 추가하는 UX까지 검증한 것은 아니다.

**성장 격차.** 훈련 없는 정책의 20화 완료 레벨은 크레스 36, 민트 21, 알펜 22, 시온 36, 제이드 40, 키사라 12였다. 이 자동 전투 정책에서 차이가 28레벨까지 벌어졌고, 훈련 사용 정책에서는 마지막 출전 6명의 차이가 2레벨로 줄었다. 공격·회복·지원·처치의 실제 EXP와 플래너의 기술 선택이 함께 만든 결과이므로 특정 병과가 항상 불리하다는 결론으로 일반화하지 않는다.

**기본 보상과 권장 레벨.** 메인 n화의 표준 적 Lv는 `2n−1`, 권장 진입/합류 훈련 Lv는 `max(1, 2n−3)`, 최초 임무 EXP는 매 화 35다. 한 동료가 1화부터 계속 출전하면서 행동 EXP·합류 훈련·개인 이야기 보상을 전혀 받지 않는 산술 하한은 20화 진입 Lv7/EXP65, 완료 Lv8/EXP0이다. 이는 실제 이번 `natural` 결과와 다른 가정이며 플레이 예상치가 아니다. 무료 훈련은 별도 성장 메뉴에서 명시적으로 실행하는 규칙을 유지했다.

**전투 길이.** 1화는 세 정책 모두 유닛 턴 57회·아군 12페이즈였다. 20화는 각각 75회/11페이즈, 33회/5페이즈, 48회/7페이즈였다. 코어 실행의 `elapsedSeconds`에는 읽기·렌더·연출·사용자 판단 시간이 없으므로 실제 플레이 소요 시간으로 환산하지 않는다.

**반복 보상.** 매 화 수호의 메달 1개가 확정되어 각 실행의 마지막 재고는 메달 20개였다. 추가 드롭 확률도 전 화 청동검 25%, 강화 갑옷 15%, 없음 60%로 동일하다. 이번 보상 난수 시드 17에서 세 정책 모두 청동검 5개(시작 지급 1개 포함), 강화 갑옷 2개가 남았다. 수호의 메달은 HP +50·마방 +8이고, 처음부터 판매하는 생명의 부적은 HP +25이므로 초기 교체·후반 중복 보상의 체감은 별도 확인 대상이다.

**무기 선택 폭.** 일반 상점 무기는 검형 청동검·철검 2종이다. 다른 7병과에는 일반 상점 무기 단계가 없고, 전용무기 10종은 개인 시련을 통해 획득하며 해금에 메인 14·15·16화 완료가 필요하다. 이 구성은 확인된 콘텐츠 범위이며 이번에 새 무기를 추가하거나 문제라고 단정하지 않았다.

| 수정 후 구매 해금 | 일반 장비 가격 |
|---|---|
| 처음부터 | 청동검 100G, 가죽 갑옷 150G, 생명의 부적 100G |
| 메인 1화 완료 | 철검 240G, 강화 갑옷 300G, 기동 장화·집중 부적·치유 휘장 각각 180G |
| 메인 4화 완료 | 수호의 메달 480G |
| 메인 5화 완료 | 단련 갑옷 650G |

**경제 감사의 범위.** 세 정책 모두 구매·매각을 전혀 하지 않아 최종 골드는 13,200G였다. 이는 시작 300G와 20화 최초 보상 합계 12,900G의 일치 확인이다. 상점 해금과 구매 가능 여부는 기록했지만, 가격의 적정성·구매 시점·실제 장비 교체의 필요성·골드 부족 여부를 검증한 결과는 아니다. 보유 장비만 고정 점수로 선택했으며 최적화된 구매·장착 판단도 수행하지 않았다.

## 재현 방법과 시뮬레이션 조건

Unity Editor의 Play Mode가 꺼진 상태에서 실제 카탈로그를 불러오는 `TalesTactics.Editor.CampaignProgressionAudit`를 실행한다. 아래는 Editor 코드 실행 API 예시다. 정책마다 **새 빈 출력 폴더**를 사용하고 이전 실행이 끝난 뒤 다음 정책을 시작한다.

```csharp
TalesTactics.Editor.CampaignProgressionAudit.Run(
    "D:/TalesTacticsHelpGuide/Logs/CampaignProgression/natural-rerun",
    "natural", 17);
```

두 번째 인수는 `natural`, `catchUp`, `rotatingCatchUp` 중 하나다. `Run`은 Editor 업데이트에 작업을 등록하고 즉시 반환한다. `CampaignProgressionAudit.Running` 또는 출력 `report.json`의 상태로 완료를 확인하고 필요하면 `CampaignProgressionAudit.Cancel()`을 호출한다. `Completed`와 `complete:true`일 때만 전체 완료다. 실패·취소·화별 500유닛 턴/600초 제한은 `Stopped`로 기록하고 승리로 바꾸지 않는다. 출력에는 `report.json`, `stages.csv`, `isolated-save/campaign.json`이 생성된다. 사용자 `Application.persistentDataPath`와 그 하위 경로는 출력 대상으로 거부한다.

현재 증거의 원본 출력은 `D:/TalesTacticsHelpGuide/Logs/CampaignProgression/{natural,catchUp,rotatingCatchUp}-final`이다. 보상 난수 스트림은 시드 17, 전투 해석기는 제품 기본 시드 17을 사용했다. 메인 20화를 끝내기 위해 중간에 적 HP·전투 결과를 덮어쓰거나 전투 중 아군 회복·레벨 주입을 하지 않았다. 시작 시 저장된 캐릭터 정보를 적용하는 과정은 실제 `BattleDirector.BeginBattle`을 따른다.

- 표준 난이도·아군 자유 선택 턴, 전술 전투·행동 EXP·확장 배치 사용. 반격/지원 반응 공격·자동 타이밍·임무 변형·CT/SPD 순서는 사용하지 않았다.
- 아군은 기존 `UtilityPlanner`, 적은 기존 `EnemyPlanner`를 사용한다. 자유 선택 턴 모드에서도 감사기는 스케줄러가 제시하는 SPD 순서대로 자동 처리하며, 사람이 행동 순서를 바꾸는 선택은 재현하지 않는다. 한 유닛 턴에 하나의 계획을 실행하며, 진행 중인 적이 모두 사라진 뒤에는 합법적인 이동 경로로 신호·출구 목표를 처리한다. 13화 구조 순서는 왼쪽이다.
- 주력 정책의 선호 순서는 크레스·민트·알펜·시온·제이드·키사라·파라·티아·벨벳·나탈리아다. 교대 정책은 합류 동료 중 출전 횟수가 적은 순서로 6명을 고르고 동률이면 이 순서를 사용한다.
- 훈련 정책은 출전 직전 권장 Lv 미만의 동료만 실제 `TacticalDevelopment.CatchUp`으로 저장한다. 승급은 실제 레벨·이야기 조건을 만족하면 `CampaignPromotion.TrySave`로 적용한다. 성장 방향·전술 특성은 기본값이다.
- 장비는 실제 보유·장착 호환·재고 규칙 안에서 고정 능력치 점수로 선택하고 저장한다. 구매·매각·개인 이야기 보상은 없다.
- 새 격리 캠페인 저장 1회와 각 화 출전 전/보상 후 2회씩, 정책당 41회의 직렬화·재로드 일치를 확인했다. 훈련·승급·장비 자체의 추가 저장 호출 수와 구분한다. 각 화 보상 후 성장도 진입 EXP + 행동 EXP + 임무 EXP의 계산과 비교했다.

카탈로그 조건 확인용 완료 플래그 fixture, 연속 코어 캠페인 실행, Unity 테스트는 서로 다른 증거다. 대화 UI·필수 후일담 전환·마우스/패드 조작·배속별 연출·수동 보스 예고 회피·연계 타이밍·재도전은 이 코어 감사의 대상이 아니다. 실제 사람의 20화 완주, 다른 PC/DPI·물리 입력·장시간 성능 검수를 완료했다고 표현하지 않는다.

## 다음 판단에 필요한 사람의 확인

1. 1–5화에서 새 동료를 발견하고 2→6명으로 편성하며, 필요한 동료의 합류 훈련을 자연스럽게 사용하는지.
2. 공격·회복·방어 역할과 주력 고정/교대 편성에서 성장 격차가 부담스러운지. 자동 정책의 격차만 보고 EXP 수치를 일괄 변경하지 않는다.
3. 실제 구매를 포함했을 때 장비 교체의 효과, 1화 메달과 초기 부적의 선택, 6화 이후 중복 메달·기존 드롭의 가치가 적절한지.
4. 11화 분할 전선의 회복역 배치, 16화 선두 생존 조건, 20화 3단계 전투의 MP·시간·재도전 부담이 적절한지.

현재 결과는 세 가지 정해진 정책으로 성장·보상·해금·저장을 이어도 완료할 수 있다는 근거다. **20화 승리만으로 플레이어 밸런스가 최종 확정되거나 장비 구매가 불필요하다고 결론내리지 않는다.**
