# 전투·대화 표현 개발안과 기존 캠페인 정리

후속 승인으로 1·2·3번도 게임에 적용했다. 최신 구현/검증은 [CombatPresentation](../CombatPresentation/README.md)를 따른다. 아래는 시안 작성 당시 기록이며 5번 초상화 대화는 아직 개발안 상태다.

사용자 요청 1·2·3·5번은 **개발안과 시안만 작성**했다. [조작 가능한 시안](proposal.html)의 네 탭에서 피해/회복, 경험치 게이지·레벨업, 방향 선택, 화자 전환과 검격 타이밍을 확인한다. 4번의 기존 6장 제거만 실제 게임에 반영했다.

## 제안

| 항목 | 개발 방향 | 변경할 주요 코드 |
|---|---|---|
| 피해·경험치 | 1080p 피해 26px·얇은 그림자·0.85초, EXP는 초상/레벨/얇은 게이지의 별도 340px 패널. 획득자별 큐와 레벨업 후 잔여 EXP 표시 | BoardEffects.Number/PresentExperience, ExperienceGain의 전후 EXP/레벨 스냅샷, BattleHud 전용 결과 패널 |
| 대기 방향 | 머리 상단+HP바를 기준으로 화면 공간에 작은 22px 화살표 4개. 38px 클릭 영역, 선택색과 이름 표시, 높이와 카메라 회전 대응 | BattleFacingHud, BoardMovementPreview의 지면 방향 표시, BattleTacticalControls |
| 스킬 효과 | 화염 시트/입자/잔불/연기, 얼음 결정·번개·물·바람·대지·빛·어둠 구분. 무기별 준비/접촉/후속 모션과 칼끝 궤적·피격 반동 동기화 | CombatEffect, SkillEffectGeometry, BoardEffects, UnitMotion, SkillPresentation 데이터 |
| 대화 | 기존 초상화 옆 이름·2–3줄 대사. 활성 화자 강조, 좁은 창은 한 명만 표시, NPC/내레이션 예외 배치 | CampaignStory.ShowStoryLine, StoryLine의 speakerId/표정/좌우 정보, FormationPortraits 재사용 |

표의 크기·시간은 시안 제안값이다. 피해·경험치 계산과 저장 규칙, 대사 보상은 표현 변경과 분리한다. 80ms 접촉 정지는 연출 계층에만 적용하며 전역 timeScale이나 턴 계산을 멈추지 않는다. 이펙트는 풀링·동시 입자 상한을 두고, 섬광/화면 흔들림 감소 설정을 연결한다. 기존 영웅 기술 및 보스60기술을 속성·무기·범위·다단·접촉 시점별로 매핑한다.

제안 순서는 UI 두 항목 → 대화 → Unity의 불꽃/검격 대표 1종씩 → 품질 확인 후 나머지 기술이다. 1920×1080·1280×720·세로/좁은 창, 글자100/130%, 지형 높이·카메라4회전·화면 끝을 확인한다. 연속/다중 EXP·다중 레벨업·Lv50·되감기·중단/재도전과 화자/NPC·스킵 후 보상 중복을 회귀 검사한다.

## 실제 적용: 기존 6장 제거

- 현재 활성 카탈로그의 임무 목록은 메인20화만 표시하며 개인 이야기30단계는 별도 메뉴를 유지한다. 이전6장 버튼을 제거했다.
- 이전 장은 출전·대사 재생·중단 전투 이어하기에서 진입하지 못한다. 이전 장이 선택된 슬롯은 새 메인1화를 준비한다.
- 기존 레벨·EXP·장비·골드·승급·완료 이력은 유지한다. 옛 중단 전투는 원본을 즉시 삭제하지 않고 이어하기를 막으며 설명을 표시한다. 새 캠페인 진행 저장은 기존 저장 정책을 따른다.
- 저장용 인덱스0–5와 해석 코드, 기존 승급 기득권, 공용 지형/캐릭터 아트는 호환을 위해 보존한다. 역사적 전투는 격리된 레거시 카탈로그 테스트로만 검사한다. 장 번호를 당겨 새 캠페인 저장과 충돌시키지 않는다.
- 새 실행본: `Builds/CurrentCampaignWindows/TalesTactics.exe` (폴더 전체 필요). 이전에 열어 둔 실행본은 이 변경을 포함하지 않는다.

## 검증

- 실제 Unity6000.6.0f1 EditMode333/333, 전체 그래픽 PlayMode132/132. 기존6장 출전/대사/이어하기 거부, 저장 성장·골드·완료 이력 유지, 새 메인 출전과 목록을 검사했다. 메인20화·개인30단계 기존 씬 회귀도 포함한다.
- API 참조 Runtime/Editor/EditMode/PlayMode4개 컴파일 통과. 이는 Unity 테스트와 별도다.
- Windows 일반 빌드 오류0/기존 경고3, 78.587975초. 새 빌드의 물리 입력 수동 플레이는 이번 범위에서 실행하지 않았다.
- 브라우저 시안은 Edge headless에서1440/1024/390 폭×4탭12조합, 가로 넘침0, JS오류0. EXP/레벨업·방향 선택·회전 매핑·화자·한 명 배치·타이밍 재생을 확인했다. 대표 데스크톱과 모바일 캡처를 시각 검토했다. 이것은 Unity UI 구현 검증이 아니다.
- [검증 수치/해시](validation.json), [브라우저 검사](browser-validation.json), [재현 도구](verify.cjs).

## 시안의 출처

UI는 HTML/CSS로 작성했고 실제 기존 전장 캡처 `Docs/MotionStatus/battle-hud.png`와 `FormationPortraits.png`를 참조한다. 대사는 레이아웃 확인용 예시다. 기존 전장 캡처에 원래 HUD가 남아 있으므로 신규 레이아웃의 Unity 적용 화면으로 해석하지 않는다.

[불꽃·검격 콘셉트](vfx-concept.png)는 내장 image_gen으로 새로 생성했다. [프롬프트와 생성 기록](image-generation.json). 실제 스프라이트 시트나 완성 효과가 아니다. 아래 타이밍 모형은 무게 이동/접촉 정지 설명용 도형이다.

개발안과 기존6장 제거는 검증 후 develop에 반영한다. 1·2·3·5번 게임 구현은 사용자 시안 검토 이후이며 main·새 공개 패키지 반영은 이번 요청에 포함하지 않는다.
