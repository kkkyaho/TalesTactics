# 검사 실행 이력

음원 제외 상태에서 실제 Unity 6000.6.0f1 EditMode 2개와 PlayMode 9개를 검사했다. PlayMode는 음악 전환 4개 묶음과 인접 회귀 5개 개별 실행이다. 6곡 구성이 없는 공개 소스에서 재생 검사를 건너뛰지 않았다. 이번에는 전체 703개 EditMode·300개 PlayMode나 전체 스테이지 진행을 반복하지 않았다.

추가 카탈로그 검사 최초 두 실행은 0개 결과였다. 이를 통과로 세지 않는다. 목록에는 300개 검사가 있었고, 동기 PlayMode 요청은 도구가 지원하지 않아 실행 전에 거부됐다. 제품 코드를 바꾸지 않고 스크립트 도메인을 다시 불러온 뒤 동일 카탈로그 검사 1개가 실제 통과했다. 나머지 인접 검사도 각 실행 전에 도메인을 다시 불러왔다. 0개 결과의 내부 근본 원인은 확정하지 않는다.

처음 결과 대기 도구는 Unity가 임시 상태 파일을 다시 생성하는 순간 파일 부재로 중단됐으며 해당 테스트가 중단됐다는 뜻은 아니다. 이후 파일 부재를 허용하고 실제 완료 결과를 확인했다. 초기 CLI 자동 준비 확인의 명령 이름 불일치, 지원되지 않는 동기 요청, 임시 재로드 도구의 문자 이스케이프 컴파일 오류도 게임 검사 실패와 구분한다. 재로드 도구는 수정 후 실행됐고 제품 C# 소스는 변경되지 않았다.

첫 일반 Windows 빌드는 BuildReport Succeeded·오류0이지만 설정 파일 바이트 보존 검사가 실패하여 build-attempt1.json의 passed=false를 그대로 보존한다. 변경된 보호 파일은 GraphicsSettings.asset 하나이며 Git 정규화 내용은 이전과 같다. 원본 CRLF가 LF로 저장됐다. 첫 결과를 최종 통과로 재분류하지 않는다.

기존 사용자 폴더는 검사 전후 5,337개 파일을 유지했다. 변경은 테스트 도구의 TestResults.xml 하나이며 파일 추가·삭제와 실제 저장·설정 변경은 없었다. 정확히 최상위 Player.log/Player-prev.log만 비교에서 제외했다. 원본 작업 폴더의 보호 파일752개, 기존 수정12개, 미추적727개, develop/main/음원 보존 브랜치는 비교 시 그대로였다.

검증은 Unity CLI·Pipeline 스킬의 분리 프로젝트 작업 흐름을 사용했다. 일반 실행본의 사람에 의한 플레이, 전곡 청취 및 반복 경계 평가는 수행하지 않았다. 빌드와 검사 자료는 로컬에 보존하고 소스·검증 기록만 게시한다. 기존 원격 음원 이력 제거는 수행하지 않는다.
최종 재빌드는 51.1569752초·오류0·경고1, 보호 파일 및 추적 빌드 입력2,343개 불변으로 통과했다. 현재 콘솔은 오류0·경고1이며 과거 버퍼의 준비 확인 오류1개와 구분한다. Performance Testing 패키지가 빌드 도중 생성한 Resources JSON/meta4개는 해당 패키지의 후처리로 삭제됐다. URP/TMP의 빌드 전후 자동 직렬화도 원래 Git 내용과 같으며 공개 변경에 포함하지 않았다. 분리 Editor는 종료 요청 후 스스로 종료했으며 강제 종료는 사용하지 않았다.
