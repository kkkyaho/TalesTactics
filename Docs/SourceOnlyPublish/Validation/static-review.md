## 소스 검토

`LocalMusicTests.cs`, `LocalMusicSceneTests.cs`, `PreparePublicSource.cs`, `Verify-Publication.ps1`과 실제 음악 선택 코드를 검토했다. 공개를 막는 코드 문제는 발견하지 못했다.

- 테스트는 로컬 음악 0곡 또는 완전한 6곡 구성을 허용하고 부분 연결·누락을 실패로 처리한다. 0곡 구성도 재생 검사를 생략하지 않으며 제품의 타이틀·거점·이야기·전투 경로를 호출한다.
- 기존 14곡, 실제 샘플 진행, 화면 전환, 실행 중 스테이지 선택, 테마 복귀, 효과음 분리, 음량 저장을 확인하도록 구성되어 있다. EditMode 2개·음악 PlayMode 4개·인접 PlayMode 5개와 일반 Windows 빌드는 이번 음원 제외 변경의 적절한 검증 범위다. 실제 실행 결과는 별도 원문 기록을 따른다.
- 준비 도구는 분리 작업본 경로를 확인하고 AudioLibrary에서 선택한 6개 연결만 제거한다. 검토 시 디스크의 라이브러리에는 기존 음악 14개·효과음 4개가 남았다. 초기 준비 영수증의 항목별 배열은 출력되지 않았으므로 그 영수증만으로 각 클립의 정체를 증명하지 않는다.
- 공개 점검 스크립트는 승인된 원격을 단일 부모로 갖는 새 커밋 1개, 비공개 커밋 6개의 조상 제외, 보호 경로 13개와 음원 블롭 6개의 제외, 허용된 파일 변경 범위를 확인한다. 실제 원격 상태나 Unity 실행 결과를 대신 검증하지 않는다. 푸시 직전 실제 원격을 다시 확인해야 한다.

## 미디어 점검

원격 기준과 최신 로컬 커밋의 변경은 총 284개 경로(추가 227·수정 57)였다.

| 형식 | 개수 |
|---|---:|
| C# | 70 |
| JSON | 135 |
| Markdown | 22 |
| Unity meta | 21 |
| PNG | 19 |
| PowerShell | 12 |
| Python | 1 |
| Shader | 1 |
| XML | 3 |

변경된 미디어·바이너리는 증거 화면 PNG 19개, 총 38,789,662바이트뿐이었다. 모두 로컬 기준 커밋의 블롭과 일치했고 PNG 시그니처와 IHDR/IDAT/IEND 청크만 포함하며 IEND 직후 파일이 끝났다. 별도 메타데이터 청크나 뒤에 붙은 파일은 없었다. 스테가노그래피나 압축 픽셀의 숨겨진 의미를 분석한 검사는 아니다.

나머지 265개는 엄격한 UTF-8로 읽혔다. NUL 문자, audio/video/zip/octet-stream 데이터 URI, 4,096자 이상 연속된 Base64 형태의 문자열은 발견되지 않았다. 점검 당시 `Docs/SourceOnlyPublish/`의 미추적 파일 10개에도 같은 이상 징후가 없었다. 이는 일반적인 바이너리 삽입 징후 검사이며 모든 인코딩을 해독한 증명은 아니다.

변경 목록에 추가·수정된 음원·영상·압축파일·실행파일 확장자는 없었다. 공개 작업본에서 남은 추적 음원은 기존 음악 WAV 14개와 효과음 WAV 4개였고, 사용자 MP3 6개는 삭제 대상으로 준비되어 있었다. 음원을 다른 이름으로 복사하거나 음원 포함 아카이브를 추가한 징후는 발견하지 못했다.

## 범위와 후속 확인

점검은 최종 공개 커밋 생성 전의 소스 상태를 대상으로 했다. 최종 후보의 조상·파일·블롭 검사는 `Verify-Publication.ps1`의 실제 결과를 따른다. Unity가 변경한 렌더 설정·폰트·아이콘 meta·프로젝트 설정은 승인된 공개 변경 밖이므로 최종 준비 과정에서 별도로 처리해야 한다.

기존 원격 부모의 과거 이력에는 사용자 음원이 이미 남아 있다. 이번 작업은 최신 공개 트리에서 음원을 제외하며, 과거 이력 삭제·강제 푸시·태그 교체를 의미하지 않는다. 검토 과정에서는 Unity 호출이나 Git 변경을 하지 않았고, 이 보고서 이외의 파일을 수정하지 않았다.
