# 캐릭터 대기 표현 — 실제 렌더 시각 검수

2026-11-02, Unity 6000.6.0f1. 이 기록은 최종 캐릭터 대기 표현의 직접 GPU 캡처 검수다. 전체 작업의 Windows 실행 검수·성능 측정·공개 릴리즈를 대신하지 않는다.

## 최종 실행과 증거

- 표현 확정 GPU5: **1/1 통과, 15.44초**. 기본/전용 장비의 10명 × 전면/좌/우/후면을 실제 SpriteRenderer와 production UnitTone shader로 URP `RenderPipeline.StandardRequest` 렌더하여 검사했다.
- DX11 경고 수정 후 GPU6: **1/1 통과, 5.64초**. 새 폴더 `e5f5f8feb712492889383b7d2683bddf`와 GPU5를 비교한 결과 **파일 SHA-256 100/100 일치, 디코딩 RGBA 100/100 일치, 채널 최대 차이 0, 누락·추가 파일 0**이다. [100장 비교 원문](idle-gpu5-gpu6-comparison.json). 아래 육안 표본과 대표 7PNG는 GPU6 화면과도 바이트가 같다.
- 전체 EditMode: **469/469 통과, 17.97초**.
- 전체 PlayMode: **281/282, 712.14초**. 대기 GPU·실제 disable/hidden callback 두 검사는 통과했다. 실패한 기존 상점 fixture를 수정한 뒤 별도 상점 재검사는 **1/1, 9.10초** 통과했다. 단일 전체 실행 282/282 통과로 합산하지 않는다. 원문: `Logs/PlaytestFeedback20261102/full-play-final1.json`, `shop-fixture-final.json`, `idle-gpu6-final.json`.
- 원본: `C:/dev/TalesTactics/Logs/PlaytestFeedback/CharacterIdle/8a00a36dbe2d46039b3efdc124d0d8a4/`, 직접 렌더된 384×384 PNG **100개**.
- 저장소 증거: [실제 PNG 비교 갤러리](../Evidence/gallery.html), [원본·복사본 SHA-256 manifest](../Evidence/manifest.json). 대표 7개 PNG를 바이트 변경 없이 복사했다. 갤러리는 원본 캡처를 표시하고 상태를 전환할 뿐 새 이미지를 합성하지 않는다.

문서 검증에서는 7개 원본·복사본·manifest SHA-256의 일치를 다시 계산했다. 로컬 Edge에서 7개 이미지가 모두 384×384로 로드되고, 상태 버튼·이미지 클릭·Enter 키 전환이 동작하며, 1280px/390px 너비에 가로 넘침과 JavaScript 오류가 없음을 확인했다.

GPU 검사는 눈 타원 면적의 2% 이상(최소 2px)에서 미세 눈 긴장에 의한 색상 변화가 있는지 검사한다. 눈 밖 차이는 필터 경계 허용 2px 이하여야 한다. 뒷모습의 얼굴 효과 해제, Clear 후 정확한 원화 복원, 발 픽셀 고정과 상체·무기 변화도 확인한다. 결과 수치와 아래 시각 판정을 구분한다.

## 시각 판정

**이 42장 표본 범위에서 최종 표현은 합격이다.** 확대된 눈동자의 위치와 눈매가 조금 바뀌고, 기존 피부 명암과 머리카락 경계가 남는다. 제이드의 안경 테두리와 알펜의 가려진 눈 주변도 유지된다. 피부를 평평한 색으로 덮는 패치나 새 눈꺼풀 선은 보이지 않는다.

전신 표본에서는 발과 아래쪽 부츠가 같은 위치에 있고, 상체·팔·무기가 작게 이동한다. 전체 몸체를 늘이거나 상하로 띄우는 모습, 눈에 띄는 옷·무기 경계 찢김은 발견하지 않았다. 캐릭터 그림과 디자인은 원본 Idle 프레임을 유지한다.

시선과 눈 긴장은 의도적으로 미세하다. 완전히 눈을 감는 애니메이션, 입 모양 변화, 새로운 표정 원화를 구현했다고 표현하지 않는다. 작은 전장 화면에서 독립적으로 크게 읽히는 표정보다 대기 움직임에 동반되는 변화다.

최종 방식에서는 피부 재구성과 새 눈꺼풀 그리기를 제거하고 현재 그려진 눈 영역의 시선·긴장만 재표본한다. GPU4에서 GPU5로 갈 때 표현 강도는 높이지 않았다. 이전 완전 눈 감기 기준의 고정 13px 문턱을 실제 눈의 투영 면적에 비례하는 문턱으로 바꾸고, 모든 캐릭터를 캡처한 뒤 의미 검사 실패를 모아 보고하도록 했다. 기존 Cast/Damage 원화의 감은 눈도 조사했지만 머리 기울기·자세가 달라 대기 프레임에 붙이지 않았다.

첫 Windows 일반 빌드의 `Build-f60267e5b72b42d097d90ddbb77d391d/build-result.json`에는 `CharacterIdle.cginc(31)`의 DX11 잠재적 미초기화 경고가 실제 BuildReport 단계 메시지로 존재했다. 셰이더 두 함수의 result를 초기화하고 마지막 단일 return으로 바꾸며, 비활성 눈의 0 반지름도 보호했다. GPU6은 이 변경 뒤의 실제 재렌더다. [수정 후 일반 Windows BuildReport](build-normal-final.json), run `5507700f6c3b43bdba372dadf230e1b3`은 **78.0067608초 성공, 오류 0, 기존 경고 4**이며 UnitTone 경고가 사라졌음을 원문의 단계별 경고 목록에서 확인했다. 남은 경고는 Pipeline 런타임 설정 부재, 기존 DEVELOPMENT_BUILD 지시문 사용, URP 디버그 셰이더 2종 제거다. 검수 최종 빌드도 **33.5064796초 성공, 오류 0·경고 7**, UnitTone 경고 없음이다. 새 Windows 전장 10장·HUD 6장의 실제 시각 평가와 여섯 축 점수는 [Windows 별도 기록](windows-visual-review.md)을 따른다.

## 한계

- 시각 확인은 확대된 정지 표본이며 연속 영상·실제 전장 배치에서의 전수 육안 검수가 아니다. 측면·후면은 GPU 수치 검사에 포함되나 이 42장 PNG의 육안 확인 대상은 아니다.
- 전용 장비의 전면 얼굴 육안 표본은 알펜·제이드다. 나머지 전용 장비는 GPU 수치 검사 범위이며 실제 PNG 전수 시각 승인으로 표현하지 않는다.
- 작은 UV 변형이므로 완전한 얼굴 리깅이나 관절 모션이 아니다. 새 원화에는 눈 위치를 별도로 등록해야 한다. 뒷모습·등록하지 않은 얼굴·flipX/flipY renderer에는 얼굴 효과 또는 대기 효과를 안전하게 끈다.
- 상체 UV 변형을 그림자 메시까지 다시 변형하지 않으므로 화면상 약 1px 이하의 차이가 생길 수 있다. 이번 검수는 프레임률·GPU 비용을 측정하지 않았다.
- 원본 PNG·Content·게임 규칙은 편집하지 않았다. 대표 증거 7개는 원본 SHA-256과 복사본 SHA-256이 모두 일치한다.
