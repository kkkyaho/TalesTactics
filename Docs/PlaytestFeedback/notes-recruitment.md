# 첫 등장과 합류

메인 첫 등장 회차 직전의 거점·편성·장비·성장에는 신규 동료를 표시하지 않는다. 첫 등장 회차의 시작 대화가 끝나 실제 전장에 들어갈 때 신규 동료 전원을 강제로 출전시킨다. 최대 6명 안에서 기존 선택 순서의 앞쪽을 유지하고 필요한 자리만 마지막부터 비운다. 해당 회차 완료 후에는 일반 편성을 따른다. 같은 회차 재시도 중에는 신규 동료의 출전을 유지한다.

크레스·민트는 1화 시작부터 함께 구조에 나서는 기존 시작 파티로 유지한다. 위 비노출·신규 강제 출전 규칙은 2~5화에 새로 합류하는 동료에게 적용한다.

새 동료의 시작 레벨은 합류 직전에 이미 등장한 전체 동료의 저장 레벨 평균이다. 대기 동료도 포함하며 동시 합류자와 아직 등장하지 않은 동료는 제외한다. 레벨 기록이 없으면 Lv1로 보고, 기존 정수 레벨 규칙에 맞춰 소수점은 내린다. 동시 합류자는 한 번 계산한 같은 평균을 받는다. 해당 레벨의 일반 기술도 해금한다.

평균은 최초 합류 때만 적용한다. 기존 저장에 신규 동료의 성장 기록이 있으면 더 높은 레벨·EXP·승급·장비·특성·이미 해금한 기술을 유지한다. 평균보다 낮은 레벨만 평균까지 올린다. 이미 첫 등장 회차를 완료한 기존 저장은 합류 기록을 추가하거나 성장치를 다시 계산하지 않는다. 구 중단 전투의 실제 등장 상태는 이어하기뿐 아니라 준비 화면의 장비·특성·상점 저장 등 체크포인트를 소비하는 모든 공통 저장 경로에서 함께 보존한다. 저장 실패 시 추가 합류 기록과 체크포인트를 함께 되돌리며, 기존 유닛 레벨과 전투 상태를 재작성하지 않는다.

합류 기록은 기존 V3 `StoryProgress`의 `crossover.recruited.<회차>` 값으로 저장한다. 완료 플래그·스테이지 인덱스·저장 버전은 바꾸지 않는다. 합류 저장에 실패하거나 예외가 생기면 신규 기록·레벨·기술·강제 편성을 되돌리고 전장 입장을 막는다. 거점의 읽기와 편성 화면 열기는 합류나 저장을 발생시키지 않는다. 미합류 동료가 있는 과거 프리셋은 이름을 숨기고 적용을 막는다.

신규 회귀는 첫 등장 전 비노출, 동시 평균과 대기 동료 포함, 첫 등장 강제 출전·6인 한도, 다음 회차 자유 편성, 저장 실패 롤백, 기존 성장 보존, 구 중단 전투 이어하기 후 합류 유지·평균 재적용 방지, 미합류 프리셋 차단을 다룬다. 준비 가이드의 기존 합류 표시 검사는 이미 첫 등장한 상태를 명시한 fixture로 유지했다. 자동 캠페인 검수도 준비 roster와 실제 강제 출전 roster를 구분한다.

최종 실제 전체 **EditMode 469/469, 17.97초**를 통과했다. 실패·건너뜀·미결정은 0이며 합류 관련 12개 케이스도 모두 통과했다. [전체 원문](Validation/editmode-final.json).

실제 전체 **PlayMode는 281/282, 712.14초**였다. 신규 합류 검사 5개는 모두 통과했다. 첫 등장 전 비노출·평균 레벨, 6인 강제 출전과 이후 일반 편성, 합류 저장 실패 시 전투 차단, 구 중단 전투 이어하기, 구 저장을 이어하기 없이 준비 화면으로 불러온 뒤 실제 저장 실패·재시도·재로드에서 합류와 성장을 보존하는 경로를 포함한다. [전체 원문과 단일 실패](Validation/playmode-full-attempt1.json).

유일한 실패는 기존 `SevenStandardWeaponCardsPurchaseEquipAndReloadThroughActualShop`의 준비 fixture였다. 주석은 모든 동료가 합류했다고 가정했지만 실제로는 5화 등장 전 상태를 만들어 벨벳·키사라가 미합류였고, 장착 대상이 없는 무기의 구매·바로 장착 버튼이 정상적으로 비활성화됐다. fixture를 5화 동료가 실제 등장한 뒤의 상태로 명시하고, 전체 동료 합류·5화 미완료·품목별 합류 착용자 존재를 확인하도록 보완했다. 제품 상점 가드와 7종 실제 카드·구매·장착·골드 차감·디스크 재로드 검사는 유지했다.

보정 후 해당 상점 표적은 **1/1, 9.10초**로 통과했다. [표적 재검사 원문](Validation/playmode-shop-final.json). 이는 전체 실행 281/282와 별개의 재검사이며, **전체 282개가 한 번의 실행에서 모두 통과한 결과는 아니다.**

Windows 최종 캠페인은 새 GUID `eaa2e9b6b9dc49ef8d3d86294088f12b`에서 **20/20화, 271.47초, 24,626 checks·175 save/reload**를 완료했다. 실제 첫 등장 전 준비 명단과 전투 강제 출전 명단을 구분한 상태로 40개 저장 비교 JSON·48PNG·최종 V3 저장의 20개 완료 플래그와 pending/checkpoint 해제를 검증했다. wrapper `passed=true`, 오류 0·종료 코드 0·강제 정리 없음이며 사용자 트리 4,959파일·2,383디렉터리는 루트 Unity 로그 두 개를 제외하고 불변이다. [사용자 항목을 생략한 파생 요약과 원문 경로·SHA](Validation/windows-campaign-summary.json) · [Player 보고서](Validation/windows-campaign-player-report.json) · [단계 manifest](Validation/windows-campaign-stage-manifest.json) · [최종 저장 검사](Validation/windows-campaign-isolated-campaign.json). 기존 합법 명령 플래너·timeScale 4의 자동 진행이며 사람의 플레이 시간·밸런스 평가는 아니다.

첫 Windows 실행도 게임은 20화를 정상 종료했으나, wrapper가 UTF-8 보고서를 PowerShell 5의 기본 CP949로 읽어 후처리에 실패했다. [실패 이력](Validation/windows-campaign-attempt1-summary.json)을 보존하고 보고서·최종 저장 읽기에 UTF-8을 명시한 뒤 위 새 GUID 전체 실행으로 다시 검증했다. 기존 실패 결과를 수정하거나 독립 보고서 재검사만으로 전체 통과를 선언하지 않았다.

합류 구현과 관련 검증은 완료했다. 전체 변경·실제 Windows 시각 표본과 한계는 [작업 보고서](README.md), [Windows 시각 검수](Validation/windows-visual-review.md), [실제 캡처 갤러리](Evidence/Windows/gallery.html)를 따른다. `develop` 반영 여부는 실제 커밋·푸시 이력에서 확인한다.
