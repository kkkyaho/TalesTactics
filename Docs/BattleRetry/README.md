# 전투 시작 상태 재도전

신규 전투는 첫 턴 이전의 편성·레벨·승급·장비·특성·성장 방향·HP/MP/SP·배치·적 구성·턴 규칙을 별도로 보관한다. 아군 명령 대기 중 시스템 메뉴의 `시작 상태로 재도전`, 또는 패배 화면의 `다시 도전`에서 확인창을 열 수 있다. 확정하면 현재 전투 진행을 버리고 같은 시작 상태에서 첫 턴을 다시 진행한다. 취소하면 현재 전투가 유지된다.

재도전은 저장된 성장·골드·장비·장 완료 상태를 변경하지 않는다. 복원 실패 시 현재 세션을 먼저 버리지 않는다. 적군 행동/연출/스토리/입문 연습/보상 저장 미완료 중에는 사용할 수 없다. 승리 후 기존 `다시 도전`은 획득한 성장을 사용하는 새 전투다. 전투 전체 행동 되감기는 별도 미구현이다.

`BattleOpening`은 진행된 턴이 없는 시작 유닛 기록과 전투 생성 옵션을 담는다. 기존 `CheckpointUnit.Apply` 검증을 재사용하여 별도 세션을 만들고, 검증 성공 후에만 현재 전투와 교체한다. 캠페인 전투뿐 아니라 훈련과 SPD/CT도 최초 스케줄러로 재시작한다. 전투용 난수는 출전 시점에서 다시 시작한다.

중단 저장 V6에는 시작 기록을 함께 보존한다. 재실행 후 이어하기에서도 출전 당시 상태로 재도전할 수 있다. 기존 V1–V5는 원래 전투 규칙으로 이어지며, 시작 기록이 없으므로 재도전 버튼이 비활성화되고 이유가 표시된다. 이전 실행본은 V6 중단 기록을 읽을 수 없으므로 되돌릴 때는 이전 백업이 필요하다. 외부 캠페인 저장 버전은2다.

## 검증

Unity 6000.6.0f1 실제 EditMode154/154(0.89초), PlayMode 전체104/104(203.63초). 이후 훈련 승리 화면의 기존 새 전투 버튼을 보존하는 조건을 보완하고, 신규 검사 포함 관련 PlayMode8/8(9.11초)을 통과했다. Runtime/Editor/Tests/PlayModeTests의 API 참조 컴파일도 통과했다.

검사 범위: 자유 턴/SPD/CT 최초 상태 재구성, 중단 저장 직렬화/이어하기 후 출전 레벨 복원, 이전 기록의 재도전 비활성화, 손상된 시작 기록 거부, 취소 시 현재 전투 유지, 재도전 시 캠페인 불변, 패배 확인/재시작과 훈련 승리 후 새 전투. 근거는 `editmode.json`, `playmode.json`, `retry-regression.json`이다.

전투 메뉴/확인창/구형 기록 안내를 1024×768,1280×800,1366×768,1920×1080,2560×1080과 글자100/130%의30조합에서 검사했다. 활성 버튼 화면 이탈0·문구 넘침0. 1024×768 글자130% 확인창/구형 기록 PNG를 직접 확인했다. 격리 임시 저장을 사용한 Editor Game View 검사이며 물리 입력으로 Windows 창을 수동 완주한 증거는 아니다. `aspect-matrix.json`, PNG 참조.

Windows 일반 빌드 `Builds/WindowsBattleRetry/TalesTactics.exe` 성공(26.274초,오류0/기존 경고10). 실행에는 폴더 전체가 필요하다. 숨김 실행12초 유지·로그 오류0, 사용자 저장3파일 SHA256 불변. 경고는 기존 Pipeline 설정/DEVELOPMENT_BUILD/비직렬화 필드 분석/셰이더 항목이다. `windows-build.json`, `windows-startup.json`, `user-save-check.json` 참조. 공개 Release 배포는 하지 않았다.
