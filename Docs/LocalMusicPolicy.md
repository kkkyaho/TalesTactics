# 사용자 제공 음원 로컬 전용

## 2026-11-26 — 앞으로 제작하는 APK에는 사용자 음원 기본 포함

사용자는 “항상 Apk만들때도 내가 제공한 음원 포함해서 만들어줘”라고 지시했다. 앞으로 APK를 만들 때는 현재 사용자 제공6곡과 기존 음악을 포함한다. 이후 교체·추가한 사용자 음원도 현재 연결대로 포함한다. 음원 제외 APK는 사용자가 명시적으로 요청한 경우에만 만든다.

별도 Android 검증 작업본에 로컬 원본 음원과 AudioLibrary 연결을 준비하고 AndroidBuild.LocalApk를 기본으로 사용한다. 빌드 전 파일·연결과 빌드 후 BuildReport의 실제 음원 포함을 확인한다. LocalApk는 음원6곡 전체 존재를 강제하지 않으므로 이름만으로 포함을 단정하지 않는다. 누락된 경우 음원 제외판으로 임의 대체해 전달하지 않는다.

이 요청은 APK 제작 기본값을 정한 것이다. MP3 원본·음원 포함 소스 이력의 원격 업로드와 새 음원 포함 APK의 공개 배포 범위는 확대하지 않는다. 기존 파일 한 개에 대한 2026-11-19 공개 예외는 유지한다. 이미 게시한 2026-11-25 음원 제외 APK를 이번 지침 변경만으로 교체하거나 다시 빌드하지 않았다. 다음 APK 제작부터 이 기본값을 적용한다.

**현재 예외:** 2026-11-19 사용자가 명시 승인한 음원 포함 Android APK 한 개와 체크섬은 공개했다. 다른 음원 원본·소스 이력·빌드의 로컬 전용 제한은 유지한다. 아래 승인 예외와 [공개 테스트판 검증](Android/LOCAL-MUSIC.md)을 따른다.

2026-11-03 사용자 요청: **“음원은 로컬커밋만 해줘”**. 사용자 제공 MP3 6곡은 로컬 파일·커밋·플레이에 보존하고 추가 원격 푸시나 해당 음원을 포함한 공개 빌드 업로드는 하지 않는다. 현재 Preview9 ZIP은 로컬 검증본으로만 보관한다. 공개 업로드 요청을 취소하고 게시 도구의 쓰기 동작을 차단했다. 이 지침과 상태 변경은 로컬 커밋으로만 기록한다.

사용자가 릴리즈 ZIP에도 음원 데이터가 포함된다는 설명을 확인한 뒤 **“그럼 원격에는 올리지 말아줘”**라고 재확인했다. 따라서 음원 원본뿐 아니라 이를 포함한 실행용 ZIP도 로컬에만 보관하며 추가 원격 업로드를 하지 않는다. 기존 원격 이력을 재작성하거나 태그를 삭제하라는 명시적 요청은 아직 없으므로 해당 이력은 현재 상태로 남아 있다.

## 로컬 보존과 원격 정리 결정

로컬 `develop`에서 정책 변경을 커밋하며, `codex/local-only-music-20261103`에 현재 커밋과 음원을 보존한다. 이 브랜치는 푸시하지 않는다. 기존 게임 에셋·AudioLibrary 연결·사용자 수정 파일·저장 파일은 바꾸지 않는다.

기존 원격 이력까지 정리하려면 여섯 음원과 관련 meta를 제거한 대체 이력을 분리된 작업 폴더에서 준비하고 검토한 후, develop/main의 기존 `e081a592…` 및 후속 커밋을 재작성하고 Preview9 태그를 교체 또는 삭제해야 한다. 강제 갱신은 기존 클론의 동기화에 영향을 주므로 정확한 범위 승인을 받기 전에는 수행하지 않는다. 로컬 음원은 보존한다. `.gitignore`나 새 삭제 커밋만으로 과거 객체가 제거되는 것은 아니며, 다른 클론·캐시에 이미 복사된 파일까지 회수했다고 보장할 수 없다.

원격용 소스는 사용자 음원이 없어도 기존 곡으로 정상 실행되는지 별도 검증해야 한다. 현재 배포 manifest·검증 기록은 이전 소스 SHA를 가리키므로 재작성한 소스의 새 배포 검증으로 재사용하지 않는다. 공개 정리 완료나 새로운 배포본 완성을 현재 주장하지 않는다.

게시 차단은 네트워크 없는 별도 검사 3건(두 쓰기 모드 차단과 읽기 전용 진입 유지)으로 확인했고, 음원 6곡이 기존 커밋과 바이트 단위로 같음을 확인했다. Unity 테스트나 원격 정리 검증으로 세지 않는다. [검사 기록](Distribution/Preview9/Validation/local-only-publication-guard.json).
