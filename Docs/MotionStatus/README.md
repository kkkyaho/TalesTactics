# 캐릭터 모션·상태창 개선

## 구현

플레이어 캐릭터10명의 기존 외형을 기준으로 새 방향별 원화760장을 추가했다. 원본 알파PNG는 `Assets/TalesTactics/Art/MotionPremium`에 있으며, 원화 생성 이력·해시·분리 결과를 이 폴더에 보관한다. 처음 제시한 `concept-*.png`는 시안이며 실제 게임 화면과 구분한다.

| 동작 | 기존 | 적용 |
|---|---:|---:|
| 보행 | 4 | 8 |
| 기본 공격 | 4 | 10 |
| 일반 기술 | 5 | 14 |
| 궁극기 | 4 | 20~22 |

각 프레임에는 앞·뒤·좌·우가 있다. 새 그림과 기존 접촉/시전/궁극기 핵심 포즈를 연결하며, 같은 캐릭터의 일반 기술은14프레임 클립을 공유한다. 모든 기술에 서로 다른14장을 새로 그렸다는 뜻이 아니다. 적10종은 기존 클립을 유지하고 공통 피격·타격 연출을 함께 사용한다.

검·클로·격투·창·활·총·방패·회복/성가에 따라 전진, 반동, 도약, 몸 기울기를 달리한다. 명중 시 공격 포즈와 효과의 짧은 정지, 피격 방향 반동과 밝은 순간 색상을 사용한다. 글로벌 시간을 멈추지 않으며 실제 HP/자원/턴 판정은 기존 Resolver 경로를 따른다. 기본 공격의 준비/회수 하한은0.32/0.40초, 기술0.42/0.50초, 궁극기0.65/0.80초이며 더 길었던 기존 값은 보존한다. 반격도 해당 기술의 시간값을 따른다.

상태창은 큰 초상·방향 회전 모델·능력/기술/장비 탭, HP/MP/SP, 실제 수치·장비 효과, 상태 지속 턴과 페이지를 제공한다. 이전/다음 또는Q/E로 같은 진영의 캐릭터를 조회하고Esc/패드 취소로 닫는다. 전투의 선택 유닛과 실제 방향은 바꾸지 않는다. 기존 성장·전술 등 보조 팝업은 별도 준비 경로를 유지한다.

- [Octopath Traveler II 공식 시스템](https://www.jp.square-enix.com/octopathtraveler2/system/): 캐릭터와 자원·능력 정보의 분리.

공식 소개의 전투/정보 구조를 참고했으며 원작 스프라이트·음원·UI를 내려받아 사용하지 않았다. 구현의 시간값은 이 프로젝트에 맞춘 값이며 원작 영상에서 프레임을 측정한 수치가 아니다.

## 재현

`Tools/MeasureMotionPremium.py`는 PNG를 변경하지 않고 알파 연결 영역, 방향 순서, 발 피벗, 외곽선을 CSV로 측정한다. 실제 임포트는 Unity Sprite Editor Data Provider로 수행했다. `MotionPremiumImporter.Import()`는 기존 클립4/5/4 기준의 일회성 업그레이드이며 이미 적용된 프로젝트에 다시 실행하지 않는다. Content 전체를 재생성하지 않는다.

`Tools/ReviewMotionStatus.ps1`는 실행 중 TestBattle의 격리 저장 경로를 사용해 상태창을 검사한다. `-Gallery`는 Play Mode에만10명×6단계 비교 장면을 만들며 Play 종료 시 버린다. 실제 화면 캡처 전 프레임 진행을 확인한다.

## 최종 검증

- 실제 Unity EditMode **202/202**, 전체 PlayMode **124/124(242.93초)** 통과. 전체 검사 후 상태창 전술 설명·아이콘·확대 창을 보완하고 관련 PlayMode **3/3(7.93초)**을 다시 통과했다. 마지막 API 참조 Runtime/Editor/EditMode/PlayMode4개 컴파일도 통과했다. ManagedChecks를 Unity 테스트로 계산하지 않는다.
- 첫 전체122/124에서 예전 한 줄 능력치·첫 페이지 반격 문구를 찾던 검사2건을 발견했다. 개별 실제 수치와 상태 페이지 조회로 갱신 후124개 전체를 재실행했다. 글자 확대 검사에서 기존 AccessibleText와의 중복 확대를 발견해 창만 확대하도록 고쳤다. 실패 기록을 보존한다.
- **1024×768/1920×1080/2560×1080 × 글자100/130% × 능력/기술/장비 × 영웅·적20종 =360조합**: TMP 넘침·화면 밖 버튼0. 한 프레임 내 검수용으로 만든 텍스트는 기존 접근성 확대값을 먼저 적용해 측정하고, 최종 실제 캡처는 프레임 진행 뒤 촬영했다. KO·모든 상태 효과·기술 페이지·실제 장비 능력치·적 공격 예고·모달 입력 차단·전투/자원/저장 불변은 관련 PlayMode가 확인한다.
- 실제 Game View 상태창6장과 전투 HUD1장,10명×6단계×4방향 모션 비교4장을 보관한다. 대표 화면을 직접 확인했다. 시안3장과 실제 캡처를 구분한다.
- 일반 Windows 빌드 **28.924초, 오류0/안내3건**, 새 아틀라스10종 포함. 안내는 기존 Pipeline 런타임 미설정과 URP 내부 DebugOccluder/DebugOcclusionTest stripping이다. 일반 바이너리에서 개발 검수 타입 제외를 확인했다.
- 개발 Windows 빌드는 네이티브 성공 로그·검수 타입 포함·독립 실행으로 확인했다. CLI 응답 제한과 Editor 지연 큐/Hub IPC 정지 때문에 개발 BuildReport JSON은 회수하지 못했으며 개발 빌드 시간/경고 개수는 집계하지 않는다. 일반 빌드의 직접 BuildReport, 개발 엔진 로그, 각 바이너리 SHA256과 실행 결과를 구분해 보관한다.
- 개발 실행본의 격리된1장 검수 **13.74초,26턴·22공격, 종료0, 오류0**. 입문 연습·구매·장착·승리·보상 저장을 확인했고 사용자 저장/백업/설정6개 SHA256이 불변이었다. 숨김 Windows 창을 시각 검수 근거로 쓰지 않는다.
- 일반 실행본: `Builds/WindowsMotionStatus/TalesTactics.exe`. 재현 도구: `Tools/BuildMotionStatus.cs.txt`(eval 호출 자체에도 충분한 timeout 필요), `Tools/RunMotionStatusReview.ps1`.

검증 후 임시 씬·캡처 사본은 Logs에 보존하고 테스트 CSV·동적 폰트·디스크의 Editor 설정을 원래대로 복원했다. 편집기 재시작은 패키지 등록 단계 이후 지연되어 Pipeline 연결과 런타임 플래그/씬 상태 복원은 확인하지 못했다. 위 테스트·빌드·독립 실행 결과는 재시작 이전에 확보한 실제 결과다.
