# 합류 동료와 무료 훈련 안내

## 반영 범위

- 거점의 출전 인원 옆에 현재 사용할 수 있는 대기 동료 수를 표시한다.
- 현재 메인 화에서 실제 합류한 동료가 있으면 이름과 함께 편성으로 연결한다. 버튼을 누르면 기존 병과 필터를 전체로 돌리고 목록을 처음부터 표시한다. 현재 화의 합류 명단을 설명하는 표시이며, 읽지 않은 알림을 뜻하지 않는다. 다음 화에서는 이전 합류 동료를 다시 표시하지 않는다.
- 편성 카드의 `이번 합류` 표시는 실제 합류한 동료에게만 표시한다. 아직 등장하지 않은 동료의 이름·초상화는 계속 숨긴다.
- 거점의 성장 메뉴는 훈련 대상이 있을 때 `성장 · 훈련`으로 표시하고, 출전 중인 저레벨 동료를 우선 연다. 편성 상세의 성장 버튼도 해당 동료가 훈련 대상이면 `무료 훈련`으로 표시한다.
- 성장 화면은 현재 레벨 → 임무 권장 레벨, 골드 소모 없음, 저장 후 적용을 안내한다. 실제 훈련은 기존 버튼을 명시적으로 눌러 저장에 성공한 경우에만 적용한다.

자동 편성, 최대 6명 제한, EXP·스탯·상품 가격, 보상, 기존 세이브 형식은 변경하지 않았다. 안내를 보거나 이동하는 것만으로 성장 기록을 새로 만들지 않는다. 훈련 모드와 저장 보호 상태의 제한도 그대로다.

## 검증 범위

`PreparationGuidanceSceneTests.cs`에 격리 임시 저장을 사용하는 PlayMode 회귀 3개를 추가했다.

1. 현재 합류 인물만 표시하고 다음 화에서는 이전 인물을 제외한다. 이전 병과 필터를 해제한 뒤 해당 화까지 실제 합류한 동료 목록을 열며 조회 과정에서 저장하지 않는다.
2. 출전 중인 저레벨 동료를 훈련 대상으로 우선 연다. 안내는 읽기 전용이며 저장 실패 시 성장/골드/디스크를 유지한다. 재시도에 성공하면 목표 레벨을 저장하고 재로드에서 확인한다.
3. 여섯 명이 출전 중일 때 안내를 이용해도 편성을 바꾸지 않고 추가 출전 제한을 지킨다. 훈련 모드는 합류 표시와 무료 훈련 실행을 허용하지 않는다.

2026-10-27 실제 Unity PlayMode 전체 **244/244 통과**(실패·건너뜀·미결정 0)에서 위 세 회귀가 모두 `Passed`다. [원본 테스트 결과](../CampaignFlowReview/2026-10-27/tests/playmode-244.json)를 보관했다. 이는 준비 화면의 조건을 직접 구성하는 기능 회귀이며 전투 승리·난이도 균형을 증명하지 않는다. 별도로 실제 Windows [1~20화 자동 진행](../CampaignFlowReview/2026-10-27-results.md)이 완료됐지만 그 실행은 무료 합류 훈련을 사용하지 않았다.

합류 배지의 버튼 소속을 보정한 뒤 실제 Windows 최종 UI 재검수에서 **1260/1260조합, 경고 0·실행 오류 0**을 확인했다. [최종 원본 보고서](Validation/report.json)를 보관했다. UI 검수 결과를 보스 방향·캐릭터 모션이나 사람이 직접 조작한 결과로 확대 해석하지 않는다.

### 실제 레이아웃 검수 계약

`UiSafeLayoutReview`의 기존 80개 상태를 유지하고 아래 4개를 기존 수집기에 추가했다. 기본 실행은 84개 상태 × 5개 해상도(1280×720, 1024×768, 1920×1080, 2560×1080, 1080×1440) × 3개 글자 크기(1.0/1.15/1.3), 총 **1260개 조합**이다. 현재 창만 사용하는 선택 실행은 84×3=252개다.

- `guidance-episode-two-hub`: 메인 2화, 출전 2명, 알펜·시온 합류 안내.
- `guidance-episode-two-formation`: 해당 편성의 `이번 합류` 배지 두 개와 미합류 숨김.
- `guidance-six-with-reserves`: 메인 5화, 출전 6명·대기 4명 거점.
- `guidance-free-training`: 민트 Lv1 → 권장 Lv7 무료 훈련 안내와 활성 버튼. 훈련을 실행하지 않는다.

추가 상태는 이미 격리 저장을 사용하는 검수 안에서 다시 분리한 메모리 캠페인으로 구성한다. 기존 수집기의 글자 넘침, 테두리·화면 경계, 버튼 겹침·클릭 가림, 아이콘 검사를 재사용한다. 완료·예외 경로에서 원래 캠페인 참조/JSON, 출전 인원, 선택 캐릭터/장비, 페이지, 필터/정렬/스크롤, 장비 초안 참조·내용을 복원한다. 성장 상태는 분리된 캠페인에만 존재하며 저장 함수를 누르지 않는다. 추가 검수 전후에 격리 프로필의 파일 목록과 바이트가 같은지도 판정한다.

첫 실제 Windows 실행에서 1260조합과 5개 요청 해상도의 수집은 완료됐고 실행 오류는 0이었다. 다만 두 편성 상태 × 5해상도 × 3글자 크기, 총 30조합에 `이번 합류`와 모델 선택 버튼의 겹침 경고가 남았다. 1024×768 및 1080×1440 실제 캡처에서는 이름·모델과 글자가 겹치지 않았으며, 배지가 투명 모델 선택 버튼의 형제 텍스트인 것이 원인이었다.

배지를 설명 대상인 모델 버튼의 자식으로 옮기고 상단 내부에 28단위 높이를 확보했다. 기존 배지 조건·이름·클릭 비차단 설정과 검수 판정은 유지하며, 이제 버튼 내부 글자 경계 검사도 적용된다. 기존 80개 상태의 수집·판정과 전투 fixture 저장 흐름은 바꾸지 않았다.

### 최종 실제 Windows 결과와 보관 캡처

2026-10-27 실행 `39dcd0acc7764802b4ac5bd25e83d585`의 완료 보고서는 **84상태 × 5해상도 × 3글자 크기 = 1260행**, 중복·누락 조합 0, `issues` 0, `errors` 0이다. 보고서의 실제 렌더 크기도 요청한 다섯 해상도와 일치한다. 원본 보고서 SHA-256은 `84a9327e925651b38572aa20f2757f861b85de01138df30acb1d30232a89f091`이다.

이 검수의 화면 전환은 버튼 `onClick.Invoke()`이며, 활성 버튼 중심에서 EventSystem 레이캐스트로 클릭 가림을 검사한다. 합류 안내 버튼 이동, 배지 ID 두 개, 6명 편성·대기 인원, 무료 훈련 안내 및 활성 상태를 확인하고, 추가 4개 상태의 전후 캠페인/편성/장비 초안·격리 프로필 파일 불변 검사를 통과했다. 배지 위치에 별도 실제 마우스 입력을 보내는 fixture는 없다. 합류한 캐릭터 카드 선택은 위 PlayMode 회귀에서 버튼 이벤트로 검증한다. 이 자동 검수를 사람의 마우스·키보드 사용성 검수나 무료 훈련 실행으로 표현하지 않는다.

## 장비·보상 현황

검 이외 일반 무기 7종을 [명시적 추가 도구와 실제 Content](../StandardWeapons/README.md)로 반영했다. 기존 철검과 같은 초기 한 단계이며 공통 가격 240G·메인 1화 완료 조건이다. 지팡이/창은 마력 +8, 발톱/권갑/활/총은 공격 +8, 방패 무기는 공격 +4·방어 +4다. 기존 사용자 에셋 값을 재생성하지 않으며 전용 무기의 수치·외형·획득 경로는 유지한다.

[실제 구매/장착 포함 20화 자동 진행](../CampaignFlowReview/2026-10-27-results.md)은 24건 구매와 매 화 재로드를 완료했다. 단일 고정 파티·구매 정책이며 가격 적정성이나 사람의 전투 시간을 확정하지 않는다. 무료 훈련을 사용하지 않은 최종 6인 레벨은 10~41로 벌어져, 안내 발견성과 늦게 편성한 동료의 성장 체감은 사람 검수가 필요하다.

메인 20화의 확정 보상은 수호 메달 1개씩인 현행 상태를 유지한다. [반복 보상 분산 설계](../StandardWeapons/reward-options.md)는 1~6화 메달을 유지하고 7~20화만 분산하는 후보와 매각 가치 차이를 계산했으며, 게임 데이터에 반영하지 않았다. 후보 A는 후반 매각 가치가 3360G에서 2410G로 줄어드므로 실제 구매·매각 체감을 먼저 확인해야 한다. 기존 보유 메달 회수/치환이나 완료 화의 소급 지급은 하지 않는다.
