# 경계를 잇는 의지 — 구현과 검증

사용자가 최신 Windows 실행본을 연 뒤 현재까지의 작업을 main에 머지하도록 요청했다. 실제 Unity 테스트와 Windows 빌드를 통과한 현재 구현을 develop → main 순서로 반영하는 소스 스냅샷이다. 직접 입력 UI 검수는 미완료이며 전체 검수 완료나 새 공개 패키지 배포를 뜻하지 않는다. 기존 공개 릴리즈 preview.5는 변경하지 않았다.

## 플레이 범위

- 새 메인 20화와 전후 대사, 순차 합류, 서로 다른 13×13 지형과 임무를 추가했다. 신규 저장은 새 메인 1화에서 시작하며, 기존 저장의 선택 장·편성은 유지한다.
- 후속 사용자 요청으로 기존6장은 현재 목록·출전·대사·이어하기에서 제거했다([변경 기록](../PresentationProposal/README.md)). 저장 호환용 인덱스0–5는 유지하고 새 메인은6–25, 개인 이야기는26–55를 사용한다.
- 열 명에게 개인 이야기·구조 순서 선택·전용 무기 시련을 하나씩 제공한다. 메인6–8/10–12/14–16화 진행과 앞 단계 완료로 해금된다. 완료 보상은 한 번이며, 이후 대사 다시 읽기는 재지급하지 않는다.
- 준비 화면의 동료의 이야기에서 캐릭터별 세 단계를 선택한다. 구조 순서 선택은 두 길을 모두 돕는 방식이며, 개인 무기를 얻지 않아도 메인 결말에 도달할 수 있다.
- 성장 메뉴의 합류 훈련으로 선택한 임무의 권장 진입 레벨까지 올릴 수 있다. 승급은 기존2장 또는 새 메인6화 완료와 원래 캐릭터 레벨 조건을 사용한다.

## 전투와 보스

고유20종(주요6·중간12·시련2), 각3개 실제 기술을 연결했다. 기존6장 다오스/골렘과 확장용 복사 에셋을 분리했으며, 초반 히아데스는 인간형으로 Spark Wave만 사용한다. 초반 골렘은 강타와 핵 재충전부터 사용한다.

- 공격은 이동·준비 예고 → 다음 자기 행동 발동 → 빈틈 순서다. 예고 위치는 고정되므로 이동 회피와 준비 취소가 가능하다.
- 주요6종의 민트 타임 스톱은 준비 취소/기절1회 뒤 실제 행동2회 동안 저항한다. 정지·수면·빈틈으로 넘긴 턴은 저항 소모로 세지 않는다.
- 소환진 점령과 연결 장치 파괴로 증원을 차단한다. 가나벨트는 분신3기를 전부 제거하면 노바가 취소된다. 소환병은 추가 경험치를 주지 않는다.
- 화염·얼음·이동 경로 지뢰·통행 봉쇄·지연 붕괴와 잔해 이동 비용을 적용한다. 붕괴는 다음 보스 턴 종료에 발생한다.
- 시젤의 대형 공격은 연결된 신호 주변에서 피하고, 볼란의 파도는 고지대에서 피한다. 오르도는 직전 아군 기술의 범위 형태를 준비 때 기록하며, 마지막으로 파괴한 장치의 자리를 점령하면 복구를 막는다.
- 11화는 서쪽 전선을 끝낸 뒤 동쪽 대기 부대로 전환한다. 대기 부대의 HP는 보존되며 행동·피격 대상에서 제외된다. 16화는 구조 신호와 출구를 연결하며 선두 아군 생존을 지킨다. 비전투 피난민 표시는 신호와 연결되어 있고, 구조된 행렬은 선두를 따른다.
- 크레스의 오리진 시련은 공격·유효 치유·방어, 서→동→북 신호, 남쪽 계약 문양을 사용한다. 다른9명도 회복 횟수·노래·케이지 중단·실제 흡혈·HP 소비·살아남은 방어 등 고유 조건을 사용한다.

## 저장

캠페인 저장 V3를 유지하며 새 완료·선택 기록과 장비를 추가한다. 중단 전투 V11, 시작 기록 V6에는 보스 준비·단계·타임 스톱 저항·위험 지역·장치 파괴 순서·분리 부대·개인 시련 진행을 보존한다. 되돌리기와 재도전도 같은 상태를 복원한다. 옛 중단 전투는 당시 적 구성과 규칙을 유지한다.

## 아트와 재현

선택된 생산용 아트는 `Assets/TalesTactics/Art/Crossover`에 있다. 내장 imagegen으로 생성한 독립 스프라이트이며 콘셉트 보드를 잘라 쓰지 않았다. 보스20종과 인간형 히아데스는 각각4방향·20포즈(80스프라이트), 장치12개, 민간인16개로 총1708개 rect를 연결했다. 공격5·일반 기술5·궁극기7프레임은 선택된 포즈를 재사용하며 쓰러짐은 별도2프레임이다.

`Tools/AuditCrossoverArt.py`는 원본 픽셀을 바꾸지 않는 알파 구성/경계 검사, `MeasureCrossoverArt.py`는 Unity rect·outline 생성이다. `CrossoverArtImporter`와 `CrossoverContentInstaller`는 공개된 카탈로그에 무조건 재실행하지 않는다. 초기 에셋 생성기 `DemoContent.Create`는 이번 작업에 사용하지 않았다.

## 검증 증거와 한계

전체 진행 기록은 [WORKING.md](WORKING.md), 실제 Unity 원본 로그/XML은 `D:/TalesTacticsCrossover/d3d2/Logs`에 있다. ManagedChecks와 API 참조 컴파일은 실제 Unity 테스트와 구분한다.

- 활성화 후 실제 EditMode333/333 (`editmode-enabled.xml`), 전체 PlayMode132/132 (`playmode-enabled.xml`). 이전 전체 PlayMode130/130과 이후 민간인 표시1/1도 각각 통과했다.
- 실제 Content60기술,40전투의 세 가지 턴 스케줄러 저장/되돌리기/재도전, 열 명의 시련 조건, 메인20화와 개인30단계의 씬·대사·보상 연결을 검사한다.
- [balance-audit.csv](balance-audit.csv)는 권장 레벨의 독립20전투에서20승리이다. 실제 이동·스킬·가드를 사용했으며 강제 처치/자원 보충은 없다. 연속 성장이나 모든 편성·난이도의 밸런스 검증을 뜻하지 않는다.
- 씬 보상 검사는 목표 충족을 위한 fixture를 사용한다. 개발 플레이어의440개 화면도 연출 fixture이며 기술 타격 대상은 시각 검사용으로 지정했다. 이 결과를 사람이60기술·50단계를 수동 완주한 결과로 표현하지 않는다.
- Windows 최종 일반/개발 빌드는 각각 오류0/경고3으로 성공했다([빌드 기록](windows-builds.json)). 실행본은 `Builds/CrossoverWindows/TalesTactics.exe`이며 폴더 전체가 필요하다. 검수 도구가 최종 일반 런타임 DLL에서 제외된 것도 확인했다. 마지막 API 참조 컴파일4개도 통과했다.
- 실제 입력 검수만 미완료다. 네트워크 허용을 묻는 Windows 보안 창은 사용자가 직접 취소해야 하므로 질문을 보냈으며, 보안 설정은 변경하지 않았다. 검수용 비개발 플레이어와 독립 저장은 [manual-review.json](manual-review.json)에 기록했다. 에이전트 검수 당시 원래 Unity/게임과 사용자 저장6개 해시를 유지했다. 이후 사용자 테스트용 일반 실행본을 열었으며, 사용자의 명시적인 main 머지 요청에 따라 이 검수 한계를 유지한 채 현재 구현을 반영한다.
