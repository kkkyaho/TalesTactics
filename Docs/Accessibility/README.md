# 9번 — 화면 비율·메뉴 입력 보강

2560×1080에서 준비 화면의 아래쪽 편성 카드와 상점 버튼이 하단 영역을 침범하던 문제를 수정했다. CanvasScaler의 Expand 모드로 논리 영역을 기준1440×900 이상 확보한다. 메뉴에는 Tab/Shift+Tab 순환과 금색 선택 테두리를 추가했고 Enter는 기존 UI Submit 경로를 사용한다. 전투 대상 선택의 Tab 동작은 유지한다.

## 화면 확인

Unity 6000.6.0f1의 실제 Game View, 격리 저장·훈련 Lv25·1장 기준이다. 시작/재출전 및 기술 목록 열기는 Editor eval로 호출했다. 자연 전투 완주나 물리 키보드로 직접 누른 증거는 아니다. Time.timeScale=1, 프레임5245→23281 진행을 기록했다.

15개 화면의 편성 카드·상점·하단 버튼·설정 창·기술 목록 표시를 확인했다. 활성 버튼의 화면 밖 경계 이탈0건(준비24/설정15/기술18개씩), 측정은 [aspect-matrix.json](aspect-matrix.json). 이는 버튼 경계 검사와 대표 화면 검수이며 모든 장/팝업의 모든 조합 검사나 글자 크기 사용자 평가는 아니다. 1024×768에서는 글자가 작으므로 실제 모니터에서의 가독성 평가는 남는다.

수정 전/후 일반 Lv1 준비 화면: [이전](ultrawide-before.png), [이후](ultrawide-after.png). 이전 캡처의 일부 글자 누락은 폰트 캐시 복원 직후 상태이며 이번 변경에서 폰트 에셋은 수정하지 않았다.

## 입력 확인

- 가상 Gamepad 사용 후 Keyboard Tab 입력으로 전환, 모달 버튼만 순환, Shift+Tab 역순, Enter1회 실행 및 닫기 검사를 추가했다. [단독 검사](keyboard-test.json).
- [금색 테두리 화면](keyboard-focus.png)은 Input System에 Tab 이벤트를 주입해 확인했다. [선택 상태](keyboard-focus.json).
- 전체 실제 Unity EditMode102/102, PlayMode73/73 통과. 기존 패드 연결 해제/재연결·전장/카메라/타이밍·한글 폰트 검사도 포함한다. 엔진 독립 ManagedChecks를 실행하거나 Unity 검사로 합산하지 않았다.
- 초기에 실행기 상태가 갱신되지 않은 단독 검사를 취소·재실행했다. EditMode 뒤 PlayMode0개로 끝난 시도2회는 유효한 통과로 계산하지 않았다. 스크립트 재로드 뒤73개 실행과 결과를 확인했다.

현재 연결된 장치는 Keyboard/Mouse뿐이다([장치 목록](device-inventory.json)). 실제 USB/Bluetooth 패드, 드라이버별 연결/해제/재연결, 모니터 DPI/전체화면 전환 및 저시력·색각 사용자 평가는 미완료다. 키보드만으로 전장 타일 이동을 포함한 완주, 키 재설정, 글자 크기 옵션이나 색각 모드는 이번에 구현하지 않았다. 9번 전체 완료로 표시하지 않는다.

빌드·7회 플레이어 회귀 및 사용자 저장 보존의 최신 수치는 [VALIDATION](../VALIDATION.md)을 따른다. 다음 구현 항목은10번 배포·업데이트 체계다.
