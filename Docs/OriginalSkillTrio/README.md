# 일반 기술 3종 원작 참고 연출 — 2026-10-16~17

크레스의 **마신검**, 제이드의 **메테오 스톰·썬더 블레이드**에 기술별 준비·이동·접촉 연출을 추가했다. 원작 게임플레이에서 관찰한 모양과 순서를 현재 SD 전술 전장에 맞게 재구성했다. 이번 범위는 일반 기술 세 개이며 비오의 개선은 포함하지 않는다.

[실제 변경 전후 영상](review.html) · [원작 관찰 구간과 해석](REFERENCES.md) · [이미지 원화 제작 기록](ART_PROVENANCE.md)

**구현·검증 완료.** 최종 원화 비율·크기·소멸 보완과 포즈 검사 보강까지 반영한 전체 PlayMode 188/188 통과. 최종 Editor/Windows에서 일반·축소 6장면씩 실제 실행했다.

## 기술별 적용

| 기술 | 실제 구현 내용 | 전술 화면에 맞춘 부분 |

기본 속도 기준 준비/이동/접촉 후 회복 시간은 각각 마신검 **0.4/0.35/0.65초**, 메테오 스톰 **0.65/0.6/1.1초**, 썬더 블레이드 **0.65/0.4/1.1초**다. 이는 이 프로젝트의 연출 설정이며 원작 영상의 정확한 프레임 수를 복제한 값이 아니다. 실제 행동은 준비와 이동이 끝나 접촉했을 때 기존 판정 경로로 이어진다.

## 구현 범위와 전투 규칙

`SkillSignatures.Resolve`가 정확히 세 기술 ID만 선택한다. 같은 속성이나 같은 공통 패턴을 쓰는 다른 기술에는 이번 전용 연출을 적용하지 않으며, 카탈로그 에셋의 위력·범위·MP 비용·효과 목록을 다시 생성하지 않는다.

`ImpactSignatures`는 준비, 이동, 접촉 모양을 기존 `ImpactPool`에 그린다. 파동·운석·전기검·착탄 흔적은 새 2×2 원화 아틀라스를 사용하고 기존 불꽃/연기 및 메시와 합성한다. 풀은 기존 최대 16개 제한을 유지하며, 다른 기술로 재사용할 때 전용 재질과 기술 구분을 초기화한다. 전용 재질과 메시의 해제도 검수 대상이다.

다중 대상은 중심의 큰 연출 한 개와 실제 대상별 작은 접촉 표시를 공유한다. 연속 운석이나 번개 가지가 늘어나도 `SkillResolver` 호출과 MP 차감은 기술 실행당 한 번이다. 각 대상의 피해와 숫자는 기존 판정 결과를 사용한다. 원작의 연속 타격 횟수나 속성 체계를 이 게임의 밸런스에 덧씌우지 않는다.

연출용 운석 배치는 정해진 수식으로 만들며 전투 난수나 `UnityEngine.Random`을 소비하지 않는다. 음향 합성 역시 별도 로컬 상태를 사용한다. 검수는 독립 복제한 판정기와 HP·MP·전투 난수 소비량을 비교해 이 경계를 확인하도록 구성했다.

## 이미지·음향·재현의 한계

- 새 효과 원화는 imagegen으로 제작한 투명 이미지다. 원작 게임에서 추출한 텍스처나 애니메이션을 사용하지 않았다. 프롬프트와 최종 파일은 [원화 기록](ART_PROVENANCE.md)에 남겼다.
- 캐릭터는 기존 SD 방향별 검격/시전 포즈를 활용한다. 원작의 3D 모델, 자유로운 근접 카메라, 모든 관절 동작을 새로 제작한 것은 아니다. 제이드의 두 주문은 공통 창 찌르기 대신 기존 시전 포즈를 유지한다.
- 마신검은 PSP Full Voice Edition, 제이드 두 기술은 확인한 Abyss 영문 전투 영상의 특징을 참고했다. 모든 판본의 프레임·색·카메라·피격 횟수가 동일하다고 주장하지 않는다. 플랫폼 확인 범위와 과노출 구간 등 관찰 한계는 [REFERENCES.md](REFERENCES.md)를 따른다.
- 효과음은 마신검의 바람/타격, 운석의 연속 충격, 전기검의 충전/방전을 표현하도록 로컬에서 합성한 준비·접촉 신호다. 원작 음성·원작 효과음·음악을 다운로드하거나 추출하지 않았다. 운석 후속 음향은 한 클립 안에 들어 있어 추가 전투 판정을 만들지 않는다.
- **실제 청취를 통한 음향 품질 평가는 미검증**이다. 코드 검사나 음소거 비교 영상만으로 원작과 같은 타격음을 달성했다고 표현하지 않는다.

## 검수 방법

`OriginalSkillTrioSceneTests`는 정확한 세 ID만 전용 연출을 선택하는지, 실제 행동에서 이동 전 HP/MP가 바뀌지 않는지, 접촉 이후 판정·HP 변화·MP 차감이 한 번인지, 대상별 피해 숫자가 맞는지 검사한다. 독립 판정기의 결과와 전투 난수 소비량, 전역 난수 불변, 카탈로그 불변, 일반/축소 효과의 동일 피해량도 비교한다. 별도 렌더 검사로 세 기술의 서로 다른 메시 형상, 유한한 좌표, 풀 재사용과 소유 리소스 해제를 확인하도록 구성했다.

`OriginalSkillTrioReview`는 실제 `BattleDirector.Execute` 경로로 **세 기술 × 일반/축소 효과**를 실행한다. 아군은 크레스·민트·제이드·파라·티아·알펜 **6명**이며 논리 유닛 수와 실제 모델 수를 함께 기록한다. 촬영용으로 위치·레벨을 맞춘 전장을 사용하고, 반응 공격과 임무 이벤트를 끄며, 기본 줌과 글자 100%를 사용한다. 이 검수 전장은 일반 캠페인을 수동 완주한 기록이 아니다.

캡처는 준비, 실제 HP 변화로 관찰한 접촉 직후, 후속 연출, 효과가 정리된 시점을 기록한다. 전체 프레임 옵션에서는 연속 PNG로 저장한다. **고정 30fps 촬영은 이미지 순서를 일정하게 만드는 방식이며 실시간 성능 벤치마크가 아니다.** 실제 해상도와 실행 결과는 각 `result.json`에 기록된 값을 사용한다.

검수는 출력 폴더 아래 새 GUID의 `isolated-save`를 만들고 `ConfigureStorage`로 저장 경로를 전환한다. 사용자 저장 경로의 `campaign*`/`settings*` 파일과 초기 설정이 안정된 뒤 격리 저장 파일의 SHA256을 각각 비교한다. 초기 창 크기 설정 저장과 기술 연출에 의한 저장 변경을 구분한다. 종료 시 고정 촬영 프레임과 백그라운드 실행 설정을 복원하며, 재시작 후 소유 VFX 메시·재질이 남는지도 확인한다.

검수기는 `UNITY_EDITOR` 또는 `TALESTACTICS_REVIEW`에서만 컴파일한다. 일반 Windows 빌드와 검수 빌드는 `CombatPresentationBuild.OriginalSkillTrioRelease` 및 `OriginalSkillTrioReview`로 구분한다. 일반 실행 DLL의 검수 타입 제외와 별도 검수 실행의 결과를 각각 확인했다.

## 결과 파일

[review.html](review.html)은 변경 전후 **양쪽 모두 TalesTactics 실제 실행 영상**을 재생한다. 왼쪽은 기존 공통 VFX, 오른쪽은 이번 원작 참고 전용 연출이다. 원작 게임 영상과 직접 나란히 놓은 비교가 아니다. 영상은 기본 음소거, 자동재생 없음으로 구성했다.

완성 영상 경로는 `Actual/demon-fang-{before,after}.mp4`, `Actual/meteor-storm-{before,after}.mp4`, `Actual/thunder-blade-{before,after}.mp4`이다. 최종 원시 촬영은 `Logs/OriginalSkillTrio/after-complete`이며 이미지 파일을 편집하지 않고 복사했다. 변경 전은 직전 공통 VFX 버전의 `after-final` 자료를 재사용했다. 두 촬영의 배치 함수·전장·기본 줌이 같고 기술별 소요 시간은 다르다.
