# 일반 무기 7종

검 이외 병과에 초기 상점 무기가 없던 공백을 한 단계의 상품으로 보완한다. 기존 철검 가격·성능·해금 조건은 그대로 두고, 새 장비 ID만 추가한다.

| ID | 이름 | 유형 | 능력치 | 구매가 | 해금 |
|---|---|---|---|---:|---|
| training-staff | 수련 지팡이 | 지팡이 | 마력 +8 | 240G | 메인 1화 완료 |
| steel-claw | 강철 발톱 | 발톱 | 공격 +8 | 240G | 메인 1화 완료 |
| steel-fist | 강철 권갑 | 권갑 | 공격 +8 | 240G | 메인 1화 완료 |
| training-spear | 수련 창 | 창 | 마력 +8 | 240G | 메인 1화 완료 |
| reinforced-bow | 강화 활 | 활 | 공격 +8 | 240G | 메인 1화 완료 |
| infantry-rifle | 보병 소총 | 총 | 공격 +8 | 240G | 메인 1화 완료 |
| steel-shield | 강철 방패 | 방패 무기 | 공격 +4 / 방어 +4 | 240G | 메인 1화 완료 |

지팡이는 민트·티아, 창은 제이드가 사용하는 마법 중심 무기다. 방패는 키사라의 **무기 슬롯**에 들어간다. 모든 상품은 해당 무기 유형에만 장착 가능하고, 캐릭터 전용 제한은 없다. 매각가는 기존 규칙대로 120G다. 전용 무기 수치·외형·획득 조건, EXP·레벨·골드 보상·드롭률은 바꾸지 않는다.

## 명시적 설치

Unity Editor에서 `TalesTactics.Editor.StandardWeaponContent.Install()`을 명시적으로 실행한다. 에디터 초기화나 에셋 임포트 때 자동 실행하지 않는다.

입력은 `Assets/TalesTactics/Art/StandardWeapons/icons.png`와 `Tools/standard-weapon-icons.csv`이다. 확인한 원화는 1774×887 RGBA이며 원본 PNG는 수정하지 않았다. TextureImporter의 NPOT 확대/축소는 `None`으로 고정하여 가져온 texture도 1774×887을 유지한다. 각 셀의 alpha > 64 연결 요소 중 가장 큰 삽화 영역에 5px 여백을 더한 사각형을 CSV에 기록했다. 이 사각형은 희미한 격자 경계 픽셀을 제외하며, Unity 하단 원점 좌표를 사용한다. Sprite Editor의 capability 검사와 이름/file ID 매핑을 거쳐 자른다. 기존에 정확한 이름의 일곱 sprite가 있으면 그대로 재사용하며, 불완전한 기존 슬라이스는 자동 덮어쓰지 않는다.

출력은 `Assets/TalesTactics/Content/StandardWeapons/*.asset` 7개와 기존 BattleCatalog의 Equipment 배열에 추가되는 참조뿐이다. 아이콘 sprite 메타데이터는 해당 **신규** atlas의 TextureImporter가 만든다. 기존 Content ID/가격/능력치/Icon/SourceNote를 다시 쓰지 않으며 재실행하면 기존 새 장비의 사용자 수정도 보존한다. 경로·ID 충돌은 설치를 중단한다. `DemoContent.Create`를 호출하지 않는다.

## 검증

- `StandardWeaponContentTests`: 실제 카탈로그 7개 매개변수 사례에서 아이콘, 기본 수치, 전체 캐릭터의 호환 유형, 잠금, 최초 메인 보상 API → 구매 → 장착 → 저장/재로드, 중복 장착 방지를 확인한다. 별도 1개는 격리 임시 Assets 폴더에서 설치 재호출이 사용자 수정값과 기존 장비를 보존하고 카탈로그 참조를 중복하지 않는지 확인한다.
- `StandardWeaponSceneTests`: 격리된 준비 화면에서 실제 상품 카드의 삽화·텍스트 넘침, 페이지 이동, 일곱 상품 구매·바로 장착·재로드를 확인한다. 추가 1개는 전체 페이지의 상품 중복/누락, 마지막 페이지에서 방어구/무기/전체 필터로 전환할 때 첫 페이지로 돌아오는지, 조회 중 저장하지 않는지를 확인한다. 준비 조건과 2000G를 명시한 UI 회귀이며 20화 연속 플레이 결과가 아니다.

2026-10-27 실제 Content에 7개 에셋과 카탈로그 참조가 존재하며, 위 표의 ID/가격/능력치/잠금/아이콘을 소스와 대조했다. 실제 Unity **EditMode 387/387**(일반 무기 회귀 8개 포함), **PlayMode 244/244**(일반 무기 UI 회귀 2개 포함)가 모두 통과했고 실패·건너뜀·미결정은 0이다. 원본 [EditMode JSON](../CampaignFlowReview/2026-10-27/tests/editmode-387-final.json)과 [PlayMode JSON](../CampaignFlowReview/2026-10-27/tests/playmode-244.json)을 보관했다.

7종 구매 UI 회귀는 모든 동료 합류·2000G의 격리 준비 fixture에서 7개를 실제 카드로 구매/착용/재로드하여 최종 320G를 확인한다. 실제 전투 승리로 해당 준비 조건을 만든 테스트는 아니다. 별도의 [실제 Windows 1~20화 자동 진행](../CampaignFlowReview/2026-10-27-results.md)은 24건·7320G 구매와 매 화 저장 왕복을 완료했다. 그 고정 파티에서는 새 무기 중 소총·방패·창·지팡이 4종을 샀으며 나머지 3종 구매가 발생한 것으로 표현하지 않는다.

별도 실제 Windows [UI1260조합](../PreparationGuidance/README.md)과 [보스 방향160조합·오리진8장](../SdPolish/origin-review.md) 검수를 완료했다. 두 보고서 모두 오류0이며 UI 경계/겹침 문제0, 보스 실제 sprite/표시 정상이다. 크레스의 최종 연속 동작 보정과 일반 Windows 빌드·시작도 [SD 후속 검수](../SdPolish/README.md)에서 완료했다. 가격 균형·사람 플레이 시간·연속 동작의 최종 품질은 기능/콘텐츠 테스트 통과만으로 확정하지 않는다.

## 반복 수호 메달 — 미적용 후속 설계

현재 메인 확정 보상 수호 메달 20개의 매각 가치는 총 4800G다(개당 240G). 실제 20화 자동 진행도 이 현행 보상으로 완료했다. [분산 후보표와 계산](reward-options.md)은 첫 6개의 메달을 유지하고 7~20화만 이미 해금된 상품으로 분산하는 설계이며 실제 보상을 변경하지 않았다.

후보 A(무기 7개, 갑옷 4개, 장신구 3개)의 후반 매각 가치는 2410G로 현행 3360G보다 950G 적다. 후보 B(무기 7개 뒤 메달 7개)는 2520G다. 일반 무기 7개를 모두 포함하면서 현재 가격·1개/화·신규 아이템 없음 조건으로 동일 매각 가치를 유지할 수 없다는 제약도 기록했다. 실제 구매·매각 체감을 보고 보상안을 따로 확정하며, 이미 지급된 메달 회수·치환이나 완료 화의 소급 지급은 하지 않는다.
